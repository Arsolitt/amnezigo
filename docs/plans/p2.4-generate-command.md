## 1. Context

`amnezigo` is a Go CLI at `/home/arsolitt/projects/amnezigo` that generates AmneziaWG v2.0 configuration files. The current architecture is imperative: users run `init` to create a server config, `add` to register peers, `export` to produce client configs, one step at a time. Each step mutates a single `awg0.conf` file on disk.

This architecture has fundamental problems:

1. **Fragile state.** The entire network topology lives in one flat INI file. Losing it means losing all peer keys. There is no separation between "what the user declared" and "what the generator produced."
2. **Non-idempotent.** Running `add laptop` twice creates a duplicate peer. Running `export laptop` regenerates I-packets with new random values and produces a different config each time (by design for fingerprint resistance), but the server config keeps stale peer entries that were never cleaned up.
3. **No batch mode.** Generating configs for 10 peers requires 10 `add` + 10 `export` commands. No single invocation produces a complete, validated output.
4. **Credential management is manual.** Users must track which keys belong to which peers. There is no `--full-reset` workflow to regenerate all keys atomically.

The declarative architecture (decided in roadmap context item 5) replaces this with a manifest + generate pipeline:

- The user declares topology in `amnezigo.json` (or `.jsonnet`).
- `amnezigo generate` reads the manifest, resolves credentials from previous output, generates shared obfuscation params once, generates per-peer I-packets, builds all configs in memory, validates them, and writes output atomically.
- The INI `awg0.conf` files become **output artifacts**, not mutable state.

This plan covers the `generate` command itself — the pipeline orchestrator. It assumes P2.1 delivers `Manifest` types, P2.2 delivers `LoadManifest()`, and P2.3 delivers `LoadCredentials()` / `PeerCredentials`.

### Patterns adopted from cheburbox

The cheburbox project (`/home/arsolitt/projects/cheburbox/generate/`) implements a similar pipeline for sing-box configs. Key patterns to adopt:

1. **Two-pass generation** (`server.go:623-720`): Pass 1 computes everything in memory (credentials, inbounds, outbounds); Pass 2 writes `[]FileOutput` to disk only on success. The `FileOutput{Path, Content}` struct decouples generation from I/O.

2. **Credential persistence** (`server.go:59-80`): `resolveCredentials()` merges persisted credentials with newly generated ones. When `FullReset` is set, persisted credentials are discarded. When a peer still exists, its keys are reused; new peers get fresh keys.

3. **Shared state across generation** (`state.go:7-14`): `ServerState` accumulates credentials, endpoints, and types during generation. In amnezigo's simpler star topology (single server), this reduces to "server obfuscation params + per-peer credentials."

4. **Config + validation separation** (`server.go:601-621`): `loadAllConfigs()` loads and validates all manifests before any generation begins. Fail-fast on invalid input.

5. **Result structs over direct writes** (`server.go:34-43`): `GenerateResult{Server, Files}` is returned to the caller, not written inside the generator. The CLI decides where and how to write.

## 2. Goal

Ship `amnezigo generate` — a new Cobra subcommand that replaces the imperative `init + add + export` flow with a single idempotent pipeline:

1. **Discover and load** the manifest file (P2.2 `LoadManifest`)
2. **Validate** manifest schema + AWG 2.0 invariants
3. **Load persisted credentials** from existing output directories (P2.3)
4. **Resolve shared obfuscation params** from manifest values (explicit or random) — generated ONCE, shared across all peers
5. **For each peer**: generate or reuse keypair + PSK
6. **For each client peer**: generate per-peer I-packets (CPS) using the peer's protocol and the shared S1
7. **Build configs**: server config (with auto-generated iptables if `MainIface` set) with all client `[Peer]` sections; per-client configs with server `[Peer]` section
8. **Validate** all generated configs (reuse P1.3 `ValidateServerConfig`)
9. **Atomic write**: only if all validation passes

**In scope (this PR):**

- New pipeline orchestrator `Generate(manifest, opts)` in `pipeline.go`
- New CLI subcommand `generate` in `internal/cli/generate.go`
- Flags: `--project`, `--output`, `--full-reset`, `--dry-run`, `--peer`, `--jpath`
- Output directory structure: `output/<peer-name>/awg0.conf`
- Two-pass generation: compute in memory, validate, then write
- Atomic writes via temp file + rename (reuse `SaveServerConfig` pattern from `manager.go:328-343`)
- Post-generation validation via `ValidateServerConfig`
- Dry-run mode: print what would be written without writing
- Per-peer filtering: `--peer phone` generates only one peer's config (but server config still contains all peers)
- Idempotent credential reuse across runs (P2.3 integration)
- Auto-generated iptables PostUp/PostDown when server peer has `MainIface` set

**Explicit out-of-scope (deferred):**

- Removal of legacy commands (`init`, `add`, `edit`, etc.) — that is P2.5
- QR code export — deferred to backlog
- Multi-server topology (mesh) — deferred to backlog
- JSON Schema generation for the manifest — deferred follow-up on P2.1
- Jsonnet library for presets (`lib/presets.libsonnet`) — P3.3
- Manifest-aware `validate` command — P3.1
- Manifest-aware `analyze` command — P3.2

## 3. Architecture Decisions

### 3.1 Pipeline location — `pipeline.go` at package root

**Decision**: create `pipeline.go` in the root `amnezigo` package. The pipeline orchestrator `Generate()` lives alongside `generator.go`, `validation.go`, and `writer.go`.

**Rationale**:

- The pipeline calls `GenerateServerConfig`, `generateCPSConfig`, `GenerateKeyPair`, `GenerateSPrefixesWithS1`, `GenerateHeaderRanges`, `GenerateJunkParamsWithForbidden`, `GeneratePostUp`, `GeneratePostDown`, `ValidateServerConfig`, `WriteServerConfig`, `WriteClientConfig` — all package-internal functions. A separate `internal/pipeline/` package would require exporting every one of these, inflating the public API surface.
- The cheburbox equivalent (`generate/server.go`) is ~800 lines in the same package as credentials, inbounds, outbounds. The pattern scales.
- Extraction into `internal/pipeline/` is deferred until P3+ when the abstraction boundary becomes clearer.

### 3.2 Pipeline input/output types

**Decision**: define `GenerateOptions` (input flags) and `GenerateResult` (output) in `pipeline.go`.

```go
// GenerateOptions controls the generate pipeline behavior.
type GenerateOptions struct {
    // ProjectDir is the root directory containing the manifest and output.
    // Defaults to current working directory.
    ProjectDir string
    // OutputDir is the directory where per-peer configs are written.
    // Defaults to ProjectDir/output.
    OutputDir string
    // FullReset regenerates all keys and obfuscation params.
    FullReset bool
    // DryRun prints what would be written without writing files.
    DryRun bool
    // PeerFilter limits generation to specific peer(s).
    // Empty means all peers. Server config always includes all peers
    // regardless of filter.
    PeerFilter []string
    // JpathDirs are additional Jsonnet library paths.
    JpathDirs []string
}

// GenerateResult holds the outcome of a generation run.
type GenerateResult struct {
    // Files contains all generated file outputs, keyed by relative path.
    Files []FileOutput
    // ServerPeer is the name of the server peer.
    ServerPeer string
    // ClientPeers is the ordered list of client peer names.
    ClientPeers []string
    // Findings contains any validation findings from post-generation checks.
    Findings []Finding
}

// FileOutput represents a generated file with its relative path and content.
type FileOutput struct {
    // RelPath is the path relative to the output directory.
    RelPath string
    // Content is the file content.
    Content []byte
}
```

**Rationale**:

- Mirrors cheburbox's `GenerateConfig` + `GenerateResult` + `FileOutput` pattern (`server.go:26-43`).
- `FileOutput` decouples generation from I/O, enabling dry-run and testing.
- `Findings` in the result allows the CLI to format and present post-generation validation results.

### 3.3 Server peer identification

**Decision**: the server peer is the peer with `endpoint` and `listen_port` set in the manifest. At most one peer may be the server. The pipeline validates this early and errors if zero or more than one server peer exists.

**Rationale**:

- This matches roadmap decision 6: "All nodes are peers in the manifest. The generator resolves topology."
- Explicit server identification (vs. convention like "first peer" or "peer named server") is unambiguous and manifest-driven.
- P2.1 will encode this constraint in the manifest schema; P2.4 relies on it.

### 3.4 Two-level obfuscation generation

**CRITICAL**: AWG 2.0 requires all peers in the same network to share the same S-prefix, H-range, and J-junk parameters. These are negotiated between server and clients — if two clients have different S/H/J values, the server cannot demultiplex their traffic. Only I-packet (CPS) configuration is per-peer.

**Decision**: the pipeline generates obfuscation parameters at two levels:

**Level 1 — Shared obfuscation (S/H/J) — generated ONCE per run:**

- S-prefixes (S1-S4) via `GenerateSPrefixesWithS1(s1)` or manifest values
- Header ranges (H1-H4) via `GenerateHeaderRanges()` or manifest values
- Junk parameters (Jc, Jmin, Jmax) via `GenerateJunkParamsWithForbidden()` or manifest values
- Result is a `ServerObfuscationConfig` used by ALL peers (server + clients)
- Values come from manifest's `obfuscation` section — preset resolution is handled by jsonnet (P3.3), the pipeline uses values as-is

**Level 2 — Per-peer CPS (I1-I5) — generated per client peer:**

- I-packet sizes (I1-I5) via `generateCPSConfig(protocol, mtu, s1, forbidden)` — note this takes the shared S1 as input
- Different on every `generate` invocation for fingerprint resistance
- Protocol-specific — each peer may override the default protocol
- Never persisted — this is correct behavior; I-packets should change over time

**Pipeline pseudocode**:

```go
// Level 1: shared params — ONCE
sharedObf := resolveObfuscation(manifest.Obfuscation)
// sharedObf contains S1-S4, H1-H4, Jc, Jmin, Jmax

// Level 2: per-peer CPS — per client
for _, peerName := range clientPeers {
    protocol := peerProtocol(manifest, peerName)
    cps := generateCPSConfig(protocol, mtu, sharedObf.S1, forbidden)
    // Build ClientObfuscationConfig: shared S/H/J + per-peer I-packets
    clientObf := ClientObfuscationConfig{
        ServerObfuscationConfig: sharedObf,
        I1: cps.I1, I2: cps.I2, I3: cps.I3, I4: cps.I4, I5: cps.I5,
    }
}
```

**What NOT to do**: calling `GenerateConfig()` per-peer. This function regenerates S-prefixes, H-ranges, and J-junk independently for each invocation, producing different shared params per peer. The resulting configs would be mutually incompatible.

**Rationale**:

- S/H params are server-wide (roadmap decision 4). Changing them requires redistributing all peer configs simultaneously.
- I-packet regeneration on every run is the current behavior in `ExportPeer` (`manager.go:269-273`) and is explicitly called out in the roadmap brainstorm ("I-packets should change over time for fingerprint resistance").
- Unlike cheburbox where credentials must be persisted (UUIDs, passwords), AWG obfuscation params are either deterministic (preset) or declared (manifest). The manifest IS the source of truth.
- Preset resolution is NOT done here — jsonnet handles preset expansion before the pipeline sees the manifest (see Fix #3, section 3.12).

### 3.5 Two-pass generation

**Decision**: the pipeline executes in two strict passes:

**Pass 1 — Compute (no I/O writes):**

1. Load manifest (P2.2)
2. Identify server peer vs client peers
3. Resolve shared obfuscation params from manifest values (explicit or random)
4. Load persisted credentials from existing output (P2.3)
5. For each peer: resolve keypair (reuse or generate) and PSK
6. Generate shared obfuscation config (S, H, J params) — once per run
7. For each client peer: generate per-peer I-packets (CPS) using shared S1 + peer's protocol
8. Build server `ServerConfig` (with auto-iptables if `MainIface` set) with all peers as `[Peer]` sections
9. Build each client `ClientConfig` with shared S/H/J + per-peer I-packets
10. Validate all configs via `ValidateServerConfig`
11. Collect all `FileOutput` entries in memory

**Pass 2 — Write (only if Pass 1 succeeds):**

1. For each `FileOutput`: create parent directory, write to `.tmp`, rename atomically
2. If any write fails: report error, leave partial output (do not delete existing output — it may contain credentials needed for recovery)

**Rationale**:

- Matches cheburbox's pattern: `generateServerWithState` computes everything before returning `GenerateResult` + `[]FileOutput`. The caller (`GenerateAll`) iterates and writes.
- Atomic per-file writes via temp+rename (existing pattern from `manager.go:328-343`) prevent partial configs from being deployed.
- Not deleting on failure is intentional: the output directory may contain credentials from a previous successful run. Deleting would lose keys.

### 3.6 Output directory structure

**Decision**: output directory defaults to `<project-dir>/output/` with per-peer subdirectories:

```text
output/
  server/
    awg0.conf     # [Interface] + all [Peer] sections
  phone/
    awg0.conf     # client [Interface] + server [Peer]
  laptop/
    awg0.conf     # client [Interface] + server [Peer]
```

**Rationale**:

- Directory names come from manifest peer keys. Simple, predictable, filesystem-safe.
- Single config file per peer (`awg0.conf`) matches AWG/WG convention.
- Server directory is named by the server peer's key in the manifest (typically `server`, but user can name it anything).

### 3.7 Reserved directory names

**Decision**: the pipeline validates that no peer name collides with reserved filesystem names. Reserved names: `.git`, `.github`, `output`, `lib`, `node_modules`, `.`, `..`.

**Rationale**:

- Peer names become directory names. A peer named `.git` would shadow the git repository.
- P2.1 should encode this constraint in the manifest schema; P2.4 validates defensively regardless.

### 3.8 Dry-run mode

**Decision**: `--dry-run` executes Pass 1 fully (including validation) and prints a summary of what would be written, then exits without writing. Output format:

```text
$ amnezigo generate --dry-run
Would write:
  output/server/awg0.conf  (1824 bytes)
  output/phone/awg0.conf   (1456 bytes)
  output/laptop/awg0.conf  (1456 bytes)

✓ All configs validated, 0 findings
```

**Rationale**:

- Full Pass 1 execution catches validation errors before any writes.
- Byte counts give the user a sense of scale.
- The summary line mirrors `validate` command output for consistency.

### 3.9 Peer filter behavior

**Decision**: `--peer phone` generates and writes only `output/phone/awg0.conf`. However, the **server config is always regenerated** when any peer filter is active, because the server config must contain all peers (adding a new peer to the manifest and running `--peer new-peer` must update the server config to include the new peer's `[Peer]` section).

**Rationale**:

- Server config is the authoritative list of peers. It must always reflect the full manifest.
- Client config is self-contained (one `[Peer]` = the server). Filtering to a single client is safe.
- This matches WireGuard semantics: the server must know all peers; clients only know the server.

### 3.10 CLI flag design

**Decision**: the `generate` subcommand has these flags:

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--project` | string | `.` (CWD) | Project directory (contains manifest + output) |
| `--output` | string | `<project>/output` | Output directory override |
| `--full-reset` | bool | `false` | Regenerate all keys and params |
| `--dry-run` | bool | `false` | Show what would be generated |
| `--peer` | string slice | empty (all) | Generate only specific peer(s) |

**Rationale**:

- `--output` override enables CI workflows where output goes to a different location.
- `--peer` is a slice to support `--peer phone --peer laptop` for partial generation.
- `--jpath` matches cheburbox and standard Jsonnet convention.

### 3.11 Error vs panic in generation

**Decision**: the pipeline returns errors, never panics. The existing generator functions (`GenerateServerConfig`, `GenerateConfig`) panic on exhausted retry budgets. The pipeline wraps these calls with `recover` and translates panics to errors.

**Rationale**:

- Panics in library code are acceptable for internal invariant violations. But the pipeline is user-facing — a panic stack trace is not user-friendly.
- The existing panic sites are in `generator.go:43`, `64`, `180`, `261`, `293` — all for retry budget exhaustion. These are extremely unlikely with normal parameters but could fire with adversarial manifest values.
- Recovery wrapper: `func safeGenerate(fn func()) error { defer func() { if r := recover(); r != nil { ... } }(); fn(); return nil }`.

### 3.12 Iptables auto-generation for server PostUp/PostDown

**Decision**: when the server peer has `MainIface` set (non-empty string in the manifest), the pipeline auto-generates `PostUp` and `PostDown` iptables rules. If `MainIface` is empty, no PostUp/PostDown is generated.

**Generated rules**:

- **PostUp**: `iptables -A FORWARD -i %i -j ACCEPT; iptables -A FORWARD -o %i -j ACCEPT; iptables -t nat -A POSTROUTING -o MAINIFACE -j MASQUERADE`
- **PostDown**: `iptables -D FORWARD -i %i -j ACCEPT; iptables -D FORWARD -o %i -j ACCEPT; iptables -t nat -D POSTROUTING -o MAINIFACE -j MASQUERADE`

Where:

- `%i` is the AWG tunnel interface placeholder, replaced by `awg-quick` at runtime with the actual interface name
- `MAINIFACE` is the value from `manifest.peers[server].main_iface`
- `TunName` defaults to `"awg0"` if not explicitly set in the manifest

**Manifest fields** (P2.1 schema):

```json
{
  "peers": {
    "server": {
      "address": "10.0.0.1/24",
      "endpoint": "vpn.example.com:51820",
      "listen_port": 51820,
      "main_iface": "eth0"
    }
  }
}
```

**Pipeline logic** (in `buildServerConfig`):

```go
if serverPeer.MainIface != "" {
    tunName := "awg0"
    if serverPeer.TunName != "" {
        tunName = serverPeer.TunName
    }
    cfg.Interface.PostUp = GeneratePostUp(tunName, serverPeer.MainIface, serverPeer.Address, false)
    cfg.Interface.PostDown = GeneratePostDown(tunName, serverPeer.MainIface, serverPeer.Address, false)
}
```

**Rationale**:

- Reuses existing `GeneratePostUp` / `GeneratePostDown` from `iptables.go:7-67`.
- Manifest-driven: the user declares `main_iface` explicitly. No guessing.
- Empty `main_iface` means no iptables rules — user may manage routing externally or use a different NAT mechanism.
- The `%i` placeholder is standard WireGuard/AmneziaWG convention, handled by `awg-quick`.

### 3.13 No preset resolution in pipeline

**Decision**: the pipeline does NOT resolve preset names to values. The manifest already contains explicit obfuscation values — preset expansion is handled by jsonnet (P3.3) before the pipeline sees the manifest.

**What this means for `resolveObfuscation`**:

- If the manifest `obfuscation` section has explicit values (S1-S4, H1-H4, Jc, Jmin, Jmax) — use them directly
- If values are missing/zero — generate random params via `GenerateServerConfig(0, 0, 0)` or individual generator functions
- No call to `GetPreset()` — presets are jsonnet-level abstractions, not pipeline concerns

**Rationale**:

- Separation of concerns: jsonnet (P3.3) handles preset expansion into concrete values. The pipeline consumes concrete values.
- A manifest produced by jsonnet evaluation already has all values resolved. A hand-written JSON manifest either has explicit values or expects random generation.
- This simplifies the pipeline: one fewer dependency, one fewer error path.

### Step B — `resolveObfuscation` helper (commit 2)

This function takes manifest obfuscation config and produces `ServerObfuscationConfig`. The manifest already contains explicit values (preset resolution is handled by jsonnet, not the pipeline). If values are present, use them as-is; if missing, generate random params.

**Test first** (`pipeline_test.go`):

```go
// resolvePeerCredentials generates or reuses keypairs and PSKs for all peers.
// When fullReset is true, all keys are regenerated regardless of persisted state.
func resolvePeerCredentials(
    peers map[string]ManifestPeer,
    persisted map[string]PeerCredentials,
    fullReset bool,
) (map[string]PeerCredentials, error) {
    result := make(map[string]PeerCredentials, len(peers))
    for name := range peers {
        if !fullReset {
            if pc, ok := persisted[name]; ok {
                result[name] = pc
                continue
            }
        }
        priv, pub := GenerateKeyPair()
        psk := GeneratePSK()
        result[name] = PeerCredentials{
            PrivateKey:   priv,
            PublicKey:    pub,
            PresharedKey: psk,
        }
    }
    return result, nil
}
```

```go
func buildServerConfig(
    manifest Manifest,
    obf ServerObfuscationConfig,
    creds map[string]PeerCredentials,
) ServerConfig {
    serverName := manifest.ServerPeerName()
    serverPeer := manifest.Peers[serverName]
    serverCreds := creds[serverName]

    cfg := ServerConfig{
        Interface: InterfaceConfig{
            PrivateKey: serverCreds.PrivateKey,
            PublicKey:  serverCreds.PublicKey,
            Address:    serverPeer.Address,
            ListenPort: serverPeer.ListenPort,
            MTU:        manifest.Network.MTU,
            DNS:        strings.Join(manifest.Network.DNS, ", "),
        },
        Obfuscation: obf,
    }

    // Auto-generate iptables PostUp/PostDown if MainIface is set.
    if serverPeer.MainIface != "" {
        tunName := "awg0"
        if serverPeer.TunName != "" {
            tunName = serverPeer.TunName
        }
        cfg.Interface.PostUp = GeneratePostUp(tunName, serverPeer.MainIface, serverPeer.Address, false)
        cfg.Interface.PostDown = GeneratePostDown(tunName, serverPeer.MainIface, serverPeer.Address, false)
    }

    // Add all non-server peers as [Peer] sections.
    for _, name := range manifest.PeerOrder() {
        if name == serverName {
            continue
        }
        peerCreds := creds[name]
        cfg.Peers = append(cfg.Peers, PeerConfig{
            Name:         name,
            PublicKey:    peerCreds.PublicKey,
            PresharedKey: peerCreds.PresharedKey,
            AllowedIPs:   manifest.Peers[name].Address,
        })
    }

    return cfg
}

func buildClientConfig(
    manifest Manifest,
    peerName string,
    obf ServerObfuscationConfig,
    creds map[string]PeerCredentials,
    defaultProtocol string,
) ClientConfig {
    serverName := manifest.ServerPeerName()
    serverPeer := manifest.Peers[serverName]
    serverCreds := creds[serverName]
    peerCreds := creds[peerName]
    peer := manifest.Peers[peerName]

    protocol := defaultProtocol
    if peer.Protocol != "" {
        protocol = peer.Protocol
    }

    mtu := manifest.Network.MTU
    if mtu == 0 {
        mtu = 1280
    }

    // Level 2: generate ONLY per-peer I-packets (CPS).
    // S/H/J shared params come from `obf` — they are NOT regenerated per peer.
    // CRITICAL: do NOT call GenerateConfig() here — it regenerates S/H/J independently.
    cps := generateCPSConfig(protocol, mtu, obf.S1, nil)

    // Build client obfuscation: shared S/H/J + per-peer I-packets.
    clientObf := ClientObfuscationConfig{
        ServerObfuscationConfig: obf,
        I1: cps.I1, I2: cps.I2, I3: cps.I3, I4: cps.I4, I5: cps.I5,
    }

    return ClientConfig{
        Interface: ClientInterfaceConfig{
            PrivateKey:  peerCreds.PrivateKey,
            Address:     peer.Address,
            DNS:         strings.Join(manifest.Network.DNS, ", "),
            MTU:         mtu,
            Obfuscation: clientObf,
        },
        Peer: ClientPeerConfig{
            PublicKey:           serverCreds.PublicKey,
            PresharedKey:        peerCreds.PresharedKey,
            Endpoint:            serverPeer.Endpoint,
            AllowedIPs:          "0.0.0.0/0, ::/0",
            PersistentKeepalive: resolveKeepalive(peer.Keepalive),
        },
    }
}
```

```go
// Generate executes the full generation pipeline: load manifest, resolve
// credentials, build configs, validate, and optionally write to disk.
func Generate(manifest Manifest, opts GenerateOptions) (GenerateResult, error) {
    // --- Pass 1: Compute ---

    // 1. Identify server peer.
    // ServerPeerName() panics if != 1 server peer — recover to return error.
    var serverName string
    func() {
        defer func() {
            if r := recover(); r != nil {
                serverName = "" // signal error path
            }
        }()
        serverName = manifest.ServerPeerName()
    }()
    if serverName == "" {
        return GenerateResult{}, fmt.Errorf("manifest must have exactly one server peer (peer with endpoint + listen_port)")
    }

    // 2. Validate peer names.
    if err := validatePeerNames(manifest); err != nil {
        return GenerateResult{}, err
    }

    // 2b. Validate client peer subnet masks (must be host masks).
    for name, peer := range manifest.Peers {
        if peer.IsServer() {
            continue // server peer may use broader mask (e.g., /24)
        }
        if !isHostMask(peer.Address) {
            return GenerateResult{}, fmt.Errorf(
                "peer %q address %q must use a host mask (/32 for IPv4, /128 for IPv6)",
                name, peer.Address)
        }
    }

    // 3. Resolve obfuscation params.
    obf, err := resolveObfuscation(manifest.Obfuscation)
    if err != nil {
        return GenerateResult{}, fmt.Errorf("resolve obfuscation: %w", err)
    }

    // 4. Load persisted credentials.
    var persisted map[string]PeerCredentials
    if !opts.FullReset {
        persisted, err = LoadCredentials(opts.OutputDir)
        if err != nil {
            // Non-fatal: first run has no persisted credentials.
            persisted = nil
        }
    }

    // 5. Resolve credentials for all peers.
    creds, err := resolvePeerCredentials(manifest.Peers, persisted, opts.FullReset)
    if err != nil {
        return GenerateResult{}, fmt.Errorf("resolve credentials: %w", err)
    }

    // 6. Build server config.
    serverCfg := buildServerConfig(manifest, obf, creds)

    // 7. Validate server config.
    findings := ValidateServerConfig(&serverCfg)

    // 8. Build client configs + collect all file outputs.
    var files []FileOutput
    defaultProtocol := manifest.Obfuscation.Protocol
    if defaultProtocol == "" {
        defaultProtocol = "random"
    }

    // Server config file.
    var serverBuf bytes.Buffer
    if err := WriteServerConfig(&serverBuf, serverCfg); err != nil {
        return GenerateResult{}, fmt.Errorf("write server config: %w", err)
    }
    files = append(files, FileOutput{
        RelPath: filepath.Join(serverName, "awg0.conf"),
        Content: serverBuf.Bytes(),
    })

    // Client config files.
    var clientPeers []string
    for _, name := range manifest.PeerOrder() {
        if name == serverName {
            continue
        }
        // Apply peer filter if set.
        if len(opts.PeerFilter) > 0 && !containsString(opts.PeerFilter, name) {
            continue
        }
        clientCfg := buildClientConfig(manifest, name, obf, creds, defaultProtocol)
        var clientBuf bytes.Buffer
        if err := WriteClientConfig(&clientBuf, clientCfg); err != nil {
            return GenerateResult{}, fmt.Errorf("write client config for %q: %w", name, err)
        }
        files = append(files, FileOutput{
            RelPath: filepath.Join(name, "awg0.conf"),
            Content: clientBuf.Bytes(),
        })
        clientPeers = append(clientPeers, name)
    }

    result := GenerateResult{
        Files:       files,
        ServerPeer:  serverName,
        ClientPeers: clientPeers,
        Findings:    findings,
    }

    // Check for validation errors.
    for _, f := range findings {
        if f.Severity == SeverityError {
            return result, fmt.Errorf("validation failed: %s", f.OneLine())
        }
    }

    // --- Pass 2: Write (only if not dry-run) ---
    if !opts.DryRun {
        if err := writeOutputFiles(opts.OutputDir, files); err != nil {
            return result, fmt.Errorf("write output: %w", err)
        }
    }

    return result, nil
}

// writeOutputFiles atomically writes all FileOutput entries to disk.
func writeOutputFiles(outputDir string, files []FileOutput) error {
    for _, f := range files {
        absPath := filepath.Join(outputDir, f.RelPath)
        dir := filepath.Dir(absPath)
        if err := os.MkdirAll(dir, 0o750); err != nil {
            return fmt.Errorf("mkdir %q: %w", dir, err)
        }
        tmpPath := absPath + ".tmp"
        if err := os.WriteFile(tmpPath, f.Content, 0o600); err != nil {
            return fmt.Errorf("write %q: %w", tmpPath, err)
        }
        if err := os.Rename(tmpPath, absPath); err != nil {
            return fmt.Errorf("rename %q: %w", absPath, err)
        }
    }
    return nil
}

func validatePeerNames(manifest Manifest) error {
    reserved := map[string]bool{
        ".git": true, ".github": true, "output": true,
        "lib": true, "node_modules": true, ".": true, "..": true,
    }
    for name := range manifest.Peers {
        if reserved[name] {
            return fmt.Errorf("peer name %q is reserved and cannot be used", name)
        }
    }
    return nil
}

func containsString(ss []string, s string) bool {
    for _, v := range ss {
        if v == s {
            return true
        }
    }
    return false
}

// resolveKeepalive returns the keepalive value for a peer.
// nil means "use default" (20 seconds), explicit 0 means disabled.
func resolveKeepalive(k *int) int {
    if k == nil {
        return 20 // default
    }
    return *k // 0 = disabled, any positive value = interval
}

// isHostMask reports whether an address string uses a host mask
// (/32 for IPv4 or /128 for IPv6). Server peers are exempt.
func isHostMask(addr string) bool {
    ip, ipNet, err := net.ParseCIDR(addr)
    if err != nil {
        return false
    }
    ones, bits := ipNet.Mask.Size()
    return ones == bits // /32 for IPv4, /128 for IPv6
}
```

```go
package cli

import (
    "fmt"
    "path/filepath"

    "github.com/spf13/cobra"

    "github.com/Arsolitt/amnezigo"
)

func NewGenerateCommand() *cobra.Command {
    var (
        projectDir string
        outputDir  string
        fullReset  bool
        dryRun     bool
        peers      []string
        jpathDirs  []string
    )

    cmd := &cobra.Command{
        Use:   "generate",
        Short: "Generate AWG configs from manifest",
        Long: `Generate AmneziaWG v2.0 configurations from a declarative manifest.

Reads amnezigo.json (or amnezigo.jsonnet) from the project directory,
resolves obfuscation parameters and credentials, generates per-peer
configs, validates them, and writes output atomically.

Output structure:
  output/<peer>/awg0.conf

Examples:
  amnezigo generate
  amnezigo generate --project /path/to/project
  amnezigo generate --full-reset
  amnezigo generate --dry-run
  amnezigo generate --peer phone --peer laptop
`,
        Args: cobra.NoArgs,
        RunE: func(cmd *cobra.Command, _ []string) error {
            return runGenerate(cmd, projectDir, outputDir, fullReset, dryRun, peers, jpathDirs)
        },
    }

    cmd.Flags().StringVar(&projectDir, "project", ".", "Project directory (contains manifest)")
    cmd.Flags().StringVar(&outputDir, "output", "", "Output directory (default: <project>/output)")
    cmd.Flags().BoolVar(&fullReset, "full-reset", false, "Regenerate all keys")
    cmd.Flags().BoolVar(&dryRun, "dry-run", false, "Show what would be generated")
    cmd.Flags().StringSliceVar(&peers, "peer", nil, "Generate only specific peer(s)")
    cmd.Flags().StringSliceVar(&jpathDirs, "jpath", nil, "Jsonnet library search paths")

    return cmd
}

func runGenerate(cmd *cobra.Command, projectDir, outputDir string, fullReset, dryRun bool, peers, jpathDirs []string) error {
    absProject, err := filepath.Abs(projectDir)
    if err != nil {
        return fmt.Errorf("resolve project dir: %w", err)
    }

    if outputDir == "" {
        outputDir = filepath.Join(absProject, "output")
    }

    if len(jpathDirs) == 0 {
        jpathDirs = []string{filepath.Join(absProject, "lib")}
    }

    manifest, err := amnezigo.LoadManifest(absProject, jpathDirs)
    if err != nil {
        return fmt.Errorf("load manifest: %w", err)
    }

    result, err := amnezigo.Generate(manifest, amnezigo.GenerateOptions{
        ProjectDir: absProject,
        OutputDir:  outputDir,
        FullReset:  fullReset,
        DryRun:     dryRun,
        PeerFilter: peers,
        JpathDirs:  jpathDirs,
    })
    if err != nil {
        return err
    }

    w := cmd.OutOrStdout()
    if dryRun {
        fmt.Fprintln(w, "Would write:")
        for _, f := range result.Files {
            fmt.Fprintf(w, "  %s  (%d bytes)\n",
                filepath.Join(outputDir, f.RelPath), len(f.Content))
        }
    } else {
        fmt.Fprintf(w, "✓ Generated %d config(s)\n", len(result.Files))
        for _, f := range result.Files {
            fmt.Fprintf(w, "  %s\n", filepath.Join(outputDir, f.RelPath))
        }
    }

    if len(result.Findings) > 0 {
        fmt.Fprintf(w, "\nFindings: %d\n", len(result.Findings))
        for _, f := range result.Findings {
            fmt.Fprintln(w, "  "+f.OneLine())
        }
    }

    return nil
}
```

## 7. Risks and Edge Cases

| Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- |
| P2.1/P2.2/P2.3 type signatures differ from assumptions in this plan | Medium | Adapter code needed | Plan documents expected interface; adapt Step B-D implementation to match actual P2.1-P2.3 types. Test-first approach catches mismatches at compile time. |
| Generator panics on adversarial manifest values (e.g. MTU=10) | Low | CLI crashes with stack trace | Wrap generator calls in recover, translate to errors (section 3.11). |
| Peer name contains filesystem-unsafe characters (spaces, slashes, unicode) | Medium | Write failure or path traversal | Validate peer names: `[a-zA-Z0-9_-]` only. Reject at manifest validation, not at write time. |
| Output directory on different filesystem than temp file | Low | Atomic rename fails (cross-device) | Write temp file in the same directory as target (already the case in `SaveServerConfig` pattern). |
| Race condition: two `generate` runs concurrently | Low | Credential corruption | Out of scope for v1. File locking deferred. Document: "do not run generate concurrently on the same project." |
| Manifest has >100 peers — performance of key generation | Very Low | Slow first run | Each `GenerateKeyPair` is ~0.1ms. 100 peers = ~10ms. Not a concern. |
| Credential persistence (P2.3) reads corrupted output config | Low | Parse error, fresh keys generated | `LoadCredentials` errors are non-fatal: fresh keys are generated. User must `--full-reset` to get clean state. |
| I-packet CPS length collides with padded S-prefix size | Low | `GenerateConfig` retries or panics | `GenerateConfig` already has retry logic and falls back to `<t>` (4 bytes). The pipeline wraps panics via recover. |
| Existing output directory has unexpected files (not from amnezigo) | Medium | Files left untouched | The pipeline only writes `awg0.conf` in per-peer directories. It does not delete anything. Stale files from removed peers remain until manually cleaned or P2.5 adds orphan handling. |
| PostUp/PostDown iptables rules require server-specific fields (tunName, mainIface) | Medium | Missing fields in manifest | Auto-generated when `MainIface` is set on server peer. If absent, no iptables rules — user manages routing externally. Reuses existing `GeneratePostUp` / `GeneratePostDown` from `iptables.go`. |
| Client config PersistentKeepalive defaults to 20 | Low | Configurable via `*int` | `PeerManifest.Keepalive` is `*int`: nil defaults to 20, explicit 0 disables. Matches common WireGuard practice. |

## 9. Out of Scope (Explicit)

The following are **deliberately excluded** from this PR:

- **Removal of legacy commands.** `init`, `add`, `edit`, `remove`, `export`, `list` remain until P2.5. Both old and new paths coexist temporarily.
- **Orphan directory cleanup.** If a peer is removed from the manifest, its output directory is NOT deleted. Documenting this is sufficient for v1.
- **QR code generation.** Deferred to backlog.
- **Multi-server / mesh topology.** Single-server star topology only.
- **JSON Schema generation.** P2.1 follow-up.
- **Jsonnet preset library** (`lib/presets.libsonnet`). P3.3 scope.
- **Manifest-aware `validate` / `analyze`.** P3.1 / P3.2 scope.
- **File locking for concurrent runs.** Not worth the complexity for v1.
- **Config diff between runs.** No "what changed since last generate" output.
- **IP address auto-assignment.** All peers must have explicit addresses in the manifest. Auto-assignment from a pool (current `AddPeer` behavior) is removed with the imperative flow.

If any of these come up during implementation, **do not include them**. Note for the next PR.
