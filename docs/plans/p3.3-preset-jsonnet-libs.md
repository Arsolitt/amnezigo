## 1. Context

`amnezigo` is a Go CLI that generates AmneziaWG configuration files. P1.5 shipped a preset system (`presets.go`) with four built-in presets (`lan-conservative`, `home-balanced`, `mobile-aggressive`, `test-minimal`). Each preset is a Go struct (`Preset`) holding all obfuscation parameters: S1-S4 padding, H1-H4 header ranges, Jc/Jmin/Jmax junk parameters, and a default protocol.

Today presets are consumed in two ways:

1. **CLI flag**: `amnezigo init --preset home-balanced` — the `init` command calls `GetPreset("home-balanced")`, converts to `GeneratorOptions`, and threads through the generator.
2. **Manifest string**: `obfuscation: { preset: "home-balanced" }` — the pipeline (P2.4) resolves the preset name at load time via `GetPreset()`.

Both paths treat presets as opaque names resolved by Go code. Users working with JSON manifests (no jsonnet) have no way to inspect or override individual preset fields — they either take the entire preset or write all parameters manually.

**What P3.3 adds**: a third consumption path — jsonnet library files that mirror every built-in preset as an importable object. Users writing `.jsonnet` manifests can:

```jsonnet
local presets = import 'presets/home-balanced.libsonnet';

{
  version: 1,
  obfuscation: presets { s1: 80 },  // override S1, keep everything else
  peers: { /* ... */ },
}
```

This enables fine-grained composition: start from a known-good preset, override one field, and still benefit from the curated baseline. JSON-only users continue using the string-name path unchanged.

**Current preset struct** (`presets.go:8-16`):

```go
type Preset struct {
    Name            string
    Description     string
    DefaultProtocol string
    H1, H2, H3, H4 HeaderRange
    MTU             int
    S1, S2, S3, S4  int
    Jc, Jmin, Jmax  int
}
```

**Current `HeaderRange`** (`types.go:6-8`):

```go
type HeaderRange struct {
    Min, Max uint32
}
```

**Current preset registry** (`presets.go:51-120`): four presets with hardcoded values, each validated by `TestPresetsValidate` and `TestPresetsHeaderRangesValid` in `presets_test.go`.

**Jsonnet integration point**: P2.2 adds `LoadManifest()` with `--jpath` defaulting to `lib/` relative to the manifest directory. The `lib/` directory is the standard location for jsonnet shared libraries (pattern adopted from cheburbox — see `docs/roadmap.md` decision 7). This plan places preset libsonnet files under `lib/presets/`, making them discoverable via the default `--jpath`.

**Key design constraint**: presets.go keeps the Go-side registry as the single source of truth. `lib/presets/*.libsonnet` mirrors the same values for jsonnet users. A sync test ensures they never drift.

## 2. Goal

Ship preset jsonnet libraries and manifest integration, end-to-end:

- **`lib/presets/` directory** with one `.libsonnet` file per built-in preset.
- **Each libsonnet** exports a jsonnet object with the same field names as `ObfuscationConfig` in the manifest schema (P2.1): `s1`, `s2`, `s3`, `s4`, `h1`, `h2`, `h3`, `h4`, `jc`, `jmin`, `jmax`, `protocol`.
- **Users can import and override**: `local base = import 'presets/home-balanced.libsonnet'; base { s1: 80 }`.
- **Built-in presets still work via string name** in JSON manifests: `"preset": "home-balanced"` resolves at pipeline time through Go code (existing path, unchanged).
- **Sync test**: a Go test that loads every `lib/presets/*.libsonnet` file, evaluates it with `go-jsonnet`, and asserts field-by-field equality against the corresponding `presetRegistry` entry.
- **Generation tooling** (optional): a `go generate` command or test helper that regenerates `lib/presets/*.libsonnet` from `presetRegistry`, ensuring one-way Go → jsonnet flow.
- **Manifest pipeline integration**: when the loader evaluates a `.jsonnet` manifest that uses `import 'presets/...'`, the preset values flow through as explicit fields in the resulting JSON — the pipeline treats them as inline obfuscation parameters, not as a preset name.

**Out of scope for this plan** (deferred):

- Community presets as `.libsonnet` files — community presets are YAML files in `presets/` (per P1.5); jsonnet mirrors are auto-generated from the Go registry only for built-in presets.
- Embedding `lib/presets/*.libsonnet` in the binary via `go:embed` — jsonnet library files are filesystem artifacts consumed by the jsonnet VM's import resolver, not by Go code. They ship alongside the manifest, not inside the binary.
- Remote preset registry or `update-presets` — P3.5.
- `amnezigo presets list` CLI subcommand showing jsonnet import paths — track separately.
- Preset versioning metadata in libsonnet files — `tested_on` and `maintained_by` are Go/YAML-side metadata, not needed in the jsonnet object.

## 4. Libsonnet Schema Design

### 4.1 Object structure

Each `lib/presets/<name>.libsonnet` exports a single jsonnet object. The field names match the manifest's `obfuscation` section (P2.1 schema) so that the import result can be used directly as the `obfuscation` value:

```jsonnet
// lib/presets/home-balanced.libsonnet
//
// Built-in preset: home-balanced
// Moderate S values and junk range. Good default for home internet
// connections where some DPI may exist but is not aggressive.
//
// AUTO-GENERATED from presets.go — do not edit manually.
// Regenerate: go generate ./...
{
  s1: 30,
  s2: 35,
  s3: 20,
  s4: 12,
  h1: { min: 100, max: 5000000 },
  h2: { min: 10000000, max: 200000000 },
  h3: { min: 400000000, max: 800000000 },
  h4: { min: 1000000000, max: 2100000000 },
  jc: 5,
  jmin: 250,
  jmax: 750,
  mtu: 1280,
  protocol: 'quic',
}
```

### 4.2 Field mapping: Go Preset → libsonnet

| Go field | Libsonnet key | Type | Notes |
| --- | --- | --- | --- |
| `S1` | `s1` | int | Padding for initiation message |
| `S2` | `s2` | int | Padding for response message |
| `S3` | `s3` | int | Padding for cookie reply |
| `S4` | `s4` | int | Padding for transport |
| `H1` | `h1` | `{ min, max }` | Header range 1; uint32 in Go, number in jsonnet |
| `H2` | `h2` | `{ min, max }` | Header range 2 |
| `H3` | `h3` | `{ min, max }` | Header range 3 |
| `H4` | `h4` | `{ min, max }` | Header range 4 |
| `Jc` | `jc` | int | Junk packet count |
| `Jmin` | `jmin` | int | Minimum junk size |
| `Jmax` | `jmax` | int | Maximum junk size |
| `MTU` | `mtu` | int | Maximum transmission unit |
| `DefaultProtocol` | `protocol` | string | Default I-packet protocol |
| `Name` | (not exported) | — | Metadata, not an obfuscation parameter |
| `Description` | (comment) | — | Rendered as a file-header comment |

### 4.3 User composition patterns

**Full preset (no overrides):**

```jsonnet
local preset = import 'presets/home-balanced.libsonnet';

{
  version: 1,
  obfuscation: preset,
  peers: { /* ... */ },
}
```

**Preset with overrides:**

```jsonnet
local preset = import 'presets/home-balanced.libsonnet';

{
  version: 1,
  obfuscation: preset { s1: 80, protocol: 'dns' },
  peers: { /* ... */ },
}
```

**Mixing presets (advanced):**

```jsonnet
local home = import 'presets/home-balanced.libsonnet';
local mobile = import 'presets/mobile-aggressive.libsonnet';

{
  version: 1,
  // Take S values from mobile, H ranges from home
  obfuscation: home {
    s1: mobile.s1,
    s2: mobile.s2,
    s3: mobile.s3,
    s4: mobile.s4,
  },
  peers: { /* ... */ },
}
```

### 4.4 Interaction with string-name presets

Two preset resolution paths coexist:

1. **String name** (`"preset": "home-balanced"` in JSON or `preset: 'home-balanced'` in jsonnet): resolved at pipeline time by Go code calling `GetPreset()`. Works for JSON-only users and simple jsonnet manifests.
2. **Jsonnet import**: the preset object is inlined into the `obfuscation` section by the jsonnet VM before the JSON reaches Go. The pipeline sees explicit field values, not a preset name. No `preset` key appears in the evaluated JSON — the fields are already resolved.

**Precedence rule**: if the evaluated JSON contains both a `preset` field AND explicit obfuscation fields (e.g., `{ "preset": "home-balanced", "s1": 80 }`), the explicit fields override the preset's defaults. This is the standard overlay behavior defined in P2.4's pipeline.

**No conflict**: jsonnet-imported presets never produce a `preset` key — they produce `s1`, `s2`, etc. directly. The `preset` key only appears when a user writes it explicitly. The two paths are structurally disjoint.

## 5. Architecture Decisions

### 5.1 Go → jsonnet generation direction (one-way)

**Decision**: `presets.go` is the single source of truth. `lib/presets/*.libsonnet` files are generated from the Go registry, never the reverse.

**Rationale**:

- The Go registry is validated at compile time (`TestPresetsValidate`, `TestPresetsHeaderRangesValid`) and enforces AWG 2.0 invariants.
- Jsonnet files are untyped; a typo in a `.libsonnet` would only be caught at manifest evaluation time.
- One-way generation eliminates the question of "which side wins on conflict."
- Adding a new built-in preset requires only editing `presets.go` and regenerating; no manual libsonnet authoring needed.

**Trade-off acknowledged**: contributors must know to run `go generate` (or rely on CI) after editing `presets.go`. The sync test (step 6.5) catches drift.

### 5.2 Libsonnet files live on the filesystem, not embedded in the binary

**Decision**: `lib/presets/*.libsonnet` files are NOT embedded via `go:embed`. They are filesystem artifacts consumed by the jsonnet VM's `FileImporter` via `--jpath`.

**Rationale**:

- The `go-jsonnet` VM resolves imports from the filesystem (or a custom importer). The `--jpath lib/` flag (P2.2) already establishes `lib/` as the jsonnet library root.
- Embedding would require a custom jsonnet importer that reads from `embed.FS` — unnecessary complexity for this scope.
- Users who distribute manifests alongside the binary already ship the `lib/` directory (or use `--jpath` to point elsewhere).
- If embedding becomes desirable later (single-binary distribution), it can be added without changing the libsonnet file format — only the importer changes.

### 5.3 File naming: one file per preset, not one monolithic library

**Decision**: `lib/presets/home-balanced.libsonnet` (one per preset), not `lib/presets.libsonnet` (one big file exporting all presets).

**Rationale**:

- Import specificity: `import 'presets/home-balanced.libsonnet'` is self-documenting. `import 'presets.libsonnet'` followed by `.homeBalanced` requires the user to know the jsonnet field name (camelCase? kebab-case?).
- Tree-shaking: jsonnet evaluates the entire imported file. One-per-preset means the user only pays for the preset they use.
- Filesystem discoverability: `ls lib/presets/` shows available presets immediately.
- Matches the `presets/*.yaml` pattern from P1.5 (one YAML per preset).

### 5.4 Field naming: snake_case for consistency with manifest schema

**Decision**: libsonnet fields use snake_case (`s1`, `h1`, `jc`, `jmin`, `jmax`, `mtu`, `protocol`) matching the manifest schema field names from P2.1.

**Rationale**: jsonnet convention leans toward snake_case or camelCase — both are valid. The manifest schema (P2.1) uses snake_case for JSON keys (`listen_port`, `post_up`, etc.). Using the same casing in libsonnet means the imported object slots directly into the `obfuscation` section without field renaming.

### 5.5 Generation mechanism: `go generate` + test guard

**Decision**: a Go file `presets_gen.go` at the repo root contains a `//go:generate` directive that runs a small generator program (or script) to produce `lib/presets/*.libsonnet` from `presetRegistry`. A sync test (`TestPresetsJsonnetSync`) verifies that the checked-in libsonnet files match the Go registry.

**Alternatives considered**:

| Approach | Pros | Cons |
| --- | --- | --- |
| `go generate` + sync test | Automated, catches drift in CI, one command to regenerate | Adds a small generator tool to the repo |
| Manual authoring + sync test | No tooling overhead | Error-prone; contributors forget to update libsonnet |
| Test-time generation (no checked-in files) | Zero drift risk | Users cannot inspect or `import` the files without building; defeats the purpose |
| Build-time generation via Makefile | Works but adds build dependency | Go-native `go generate` is more idiomatic |

**Choice**: `go generate` + sync test is the standard Go pattern for generated files. The sync test is the safety net.

### 5.6 Header range representation

**Decision**: header ranges are represented as `{ min: N, max: N }` objects in libsonnet, matching the `HeaderRange` struct. The keys `min` and `max` are lowercase to match jsonnet convention and the YAML preset schema from P1.5.

**Note on uint32**: Go's `HeaderRange.Min` and `HeaderRange.Max` are `uint32`. Jsonnet numbers are IEEE 754 doubles, which can represent all uint32 values exactly (max uint32 = 4,294,967,295 < 2^53). No precision loss.

package amnezigo

import (
    "fmt"
    "strings"

// GeneratePresetLibsonnet produces the jsonnet source for a single preset.
// The output is a self-contained .libsonnet file that exports one object
// with all obfuscation fields.
func GeneratePresetLibsonnet(p Preset) string {
    var b strings.Builder
    fmt.Fprintf(&b, "// lib/presets/%s.libsonnet\n", p.Name)
    fmt.Fprintf(&b, "//\n")
    fmt.Fprintf(&b, "// Built-in preset: %s\n", p.Name)
    fmt.Fprintf(&b, "// %s\n", p.Description)
    fmt.Fprintf(&b, "//\n")
    fmt.Fprintf(&b, "// AUTO-GENERATED from presets.go — do not edit manually.\n")
    fmt.Fprintf(&b, "// Regenerate: go generate ./...\n")
    fmt.Fprintf(&b, "{\n")
    fmt.Fprintf(&b, "  s1: %d,\n", p.S1)
    fmt.Fprintf(&b, "  s2: %d,\n", p.S2)
    fmt.Fprintf(&b, "  s3: %d,\n", p.S3)
    fmt.Fprintf(&b, "  s4: %d,\n", p.S4)
    fmt.Fprintf(&b, "  h1: { min: %d, max: %d },\n", p.H1.Min, p.H1.Max)
    fmt.Fprintf(&b, "  h2: { min: %d, max: %d },\n", p.H2.Min, p.H2.Max)
    fmt.Fprintf(&b, "  h3: { min: %d, max: %d },\n", p.H3.Min, p.H3.Max)
    fmt.Fprintf(&b, "  h4: { min: %d, max: %d },\n", p.H4.Min, p.H4.Max)
    fmt.Fprintf(&b, "  jc: %d,\n", p.Jc)
    fmt.Fprintf(&b, "  jmin: %d,\n", p.Jmin)
    fmt.Fprintf(&b, "  jmax: %d,\n", p.Jmax)
    fmt.Fprintf(&b, "  mtu: %d,\n", p.MTU)
    fmt.Fprintf(&b, "  protocol: '%s',\n", p.DefaultProtocol)
    fmt.Fprintf(&b, "}\n")
    return b.String()
}
```

import (
    "fmt"
    "os"
    "path/filepath"

    "github.com/Arsolitt/amnezigo"

func main() {
    outDir := filepath.Join("lib", "presets")

        fmt.Fprintf(os.Stderr, "mkdir %s: %v\n", outDir, err)

        path := filepath.Join(outDir, p.Name+".libsonnet")

            fmt.Fprintf(os.Stderr, "write %s: %v\n", path, err)
            os.Exit(1)
        }
        fmt.Printf("wrote %s\n", path)
    }
}
```

#### Step 1.6 — Write the sync test

Create `presets_jsonnet_test.go` at the repo root:

```go
package amnezigo

import (
    "encoding/json"
    "os"
    "path/filepath"
    "testing"

    jsonnet "github.com/google/go-jsonnet"
)

// TestPresetsJsonnetSync verifies that every lib/presets/*.libsonnet file
// matches the corresponding entry in presetRegistry field-by-field.
// This is the drift guard: if presets.go is edited without regenerating
// the libsonnet files, this test fails.
func TestPresetsJsonnetSync(t *testing.T) {
    presets := ListPresets()
    if len(presets) == 0 {
        t.Fatal("ListPresets returned empty list")
    }

    vm := jsonnet.MakeVM()

    for _, p := range presets {
        t.Run(p.Name, func(t *testing.T) {
            path := filepath.Join("lib", "presets", p.Name+".libsonnet")
            data, err := os.ReadFile(path)
            if err != nil {
                t.Fatalf("read %s: %v (run 'go generate ./...' to create)", path, err)
            }

            jsonStr, err := vm.EvaluateAnonymousSnippet(path, string(data))
            if err != nil {
                t.Fatalf("evaluate %s: %v", path, err)
            }

            var obj map[string]any
            if err := json.Unmarshal([]byte(jsonStr), &obj); err != nil {
                t.Fatalf("unmarshal %s output: %v", path, err)
            }

            // Assert scalar fields.
            assertIntField(t, p.Name, obj, "s1", p.S1)
            assertIntField(t, p.Name, obj, "s2", p.S2)
            assertIntField(t, p.Name, obj, "s3", p.S3)
            assertIntField(t, p.Name, obj, "s4", p.S4)
            assertIntField(t, p.Name, obj, "jc", p.Jc)
            assertIntField(t, p.Name, obj, "jmin", p.Jmin)
            assertIntField(t, p.Name, obj, "jmax", p.Jmax)
            assertIntField(t, p.Name, obj, "mtu", p.MTU)
            assertStringField(t, p.Name, obj, "protocol", p.DefaultProtocol)

            // Assert header ranges.
            assertHeaderRange(t, p.Name, obj, "h1", p.H1)
            assertHeaderRange(t, p.Name, obj, "h2", p.H2)
            assertHeaderRange(t, p.Name, obj, "h3", p.H3)
            assertHeaderRange(t, p.Name, obj, "h4", p.H4)
        })
    }
}

// TestPresetsLibsonnetCompleteness verifies that every preset in the
// registry has a corresponding .libsonnet file and vice versa.
func TestPresetsLibsonnetCompleteness(t *testing.T) {
    presets := ListPresets()
    presetNames := make(map[string]bool)
    for _, p := range presets {
        presetNames[p.Name] = true
        path := filepath.Join("lib", "presets", p.Name+".libsonnet")
        if _, err := os.Stat(path); err != nil {
            t.Errorf("preset %q has no libsonnet file at %s", p.Name, path)
        }
    }

    // Check for orphan libsonnet files.
    entries, err := os.ReadDir(filepath.Join("lib", "presets"))
    if err != nil {
        t.Fatalf("read lib/presets/: %v", err)
    }
    for _, e := range entries {
        if filepath.Ext(e.Name()) != ".libsonnet" {
            continue
        }
        name := e.Name()[:len(e.Name())-len(".libsonnet")]
        if !presetNames[name] {
            t.Errorf("orphan libsonnet file %s has no matching preset in registry", e.Name())
        }
    }
}
```

#### Step 2.2 — Implement preset resolution in pipeline

In `pipeline.go` (from P2.4), within the `Generate()` function where `manifest.Obfuscation` is processed:

```go
func resolveObfuscation(obf ManifestObfuscation) (ServerObfuscationConfig, string, error) {
    // If a preset name is specified, load it as the base.
    var base ServerObfuscationConfig
    protocol := obf.Protocol
    if obf.Preset != "" {
        preset, err := GetPreset(obf.Preset)
        if err != nil {
            return ServerObfuscationConfig{}, "", fmt.Errorf("resolve preset: %w", err)
        }
        base = preset.ToServerObfuscation()
        if protocol == "" {
            protocol = preset.DefaultProtocol
        }
    }

    // Explicit fields override preset defaults.
    // If no preset was specified, explicit fields are the only source.
    if obf.S1 != nil { base.S1 = *obf.S1 }
    if obf.S2 != nil { base.S2 = *obf.S2 }
    if obf.S3 != nil { base.S3 = *obf.S3 }
    if obf.S4 != nil { base.S4 = *obf.S4 }
    // ... same for H1-H4, Jc, Jmin, Jmax ...
    if obf.Protocol != "" { protocol = obf.Protocol }

    return base, protocol, nil
}
```

**Key semantics**: explicit fields in `ManifestObfuscation` use pointer types (`*int`, `*HeaderRange`). A nil pointer means "not specified by user" → use preset or default. A non-nil pointer means "user override" → always wins. This is the same nil-vs-set pattern as `GeneratorOptions` (P1.5 § 5.3).

For jsonnet-imported presets: the jsonnet VM evaluates the import and produces JSON with all fields set as concrete values. The loader deserializes them into non-nil `*int` fields. From the pipeline's perspective, these are explicit overrides — no `preset` key appears. The pipeline correctly treats them as inline parameters.

## 9. Risks and Edge Cases

| Risk | Mitigation |
| --- | --- |
| **Libsonnet drift** — presets.go edited without regenerating libsonnet files | `TestPresetsJsonnetSync` fails in CI. Error message instructs: "run `go generate ./...` to regenerate". |
| **Orphan libsonnet files** — a preset is removed from Go but its libsonnet remains | `TestPresetsLibsonnetCompleteness` detects orphans and fails. |
| **Jsonnet field name mismatch with manifest schema** — libsonnet uses `s1` but manifest expects `S1` | Both use lowercase `s1` (snake_case, per P2.1 decision). Sync test compiles against the actual manifest schema struct to catch case mismatches. |
| **Header range precision loss in jsonnet** — uint32 values exceed double precision | IEEE 754 double can represent all integers up to 2^53. Max uint32 (4,294,967,295) is well within range. No precision loss. |
| **`go-jsonnet` not in go.mod when PR 1 starts** | The sync test imports `go-jsonnet`. If P2.2 has not merged, add `go-jsonnet` as a test-only dependency in PR 1. This is clean — test dependencies do not affect the binary. |
| **`--jpath` default does not match import path** | PR 2 step 2.3 explicitly verifies the `--jpath` default from P2.2 and adjusts the import convention if needed. The integration test catches mismatches. |
| **User writes both `preset:` and imports a libsonnet** — e.g., `obfuscation: preset { preset: 'other' }` | The pipeline resolves `preset:` string first, then applies overrides. If the user imports one preset's fields and also specifies a different `preset:` string, the string-name preset is loaded as the base and the imported fields override it. This is consistent but confusing. Document in user-facing docs: "Use either string-name OR import, not both." |
| **Community presets do not get libsonnet files** | Correct — community presets are YAML in `presets/` (P1.5), consumed by Go embed. Libsonnet generation covers only built-in presets from `presetRegistry`. If community demand arises, extend the generator to also read embedded YAML presets. |
| **Generator command fails silently on write error** | `cmd/gen-presets/main.go` exits non-zero on any error. CI can run `go generate ./...` and check exit code. |
| **Jsonnet evaluation error in sync test** — syntax error in generated file | The test calls `vm.EvaluateAnonymousSnippet` and reports the jsonnet error with file path. Since files are machine-generated, syntax errors indicate a bug in `GeneratePresetLibsonnet`. |

## 11. Out of Scope (Explicit)

The following are **deliberately excluded** from this plan:

- **Community preset libsonnet files** — community presets are YAML in `presets/` (P1.5). Libsonnet generation covers only built-in presets. Extending to community presets is a separate effort.
- **Embedding libsonnet files in the binary** — jsonnet VM resolves imports from the filesystem. Embedding requires a custom importer; deferred until single-binary distribution is needed.
- **`amnezigo presets list --format jsonnet`** — showing import paths in CLI output; track separately.
- **Preset versioning in libsonnet** — `tested_on`, `maintained_by`, and other metadata are Go/YAML-side concerns, not needed in the jsonnet object.
- **Remote preset registry** — P3.5.
- **Custom jsonnet importer for embedded presets** — deferred; see embedding decision in § 5.2.
- **Refactoring `presets.go` to eliminate duplication** — the Go registry and libsonnet files are intentionally separate representations. The sync test is the bridge.
- **Supporting `.jsonnet` preset files as first-class preset format** — presets are authored in Go; libsonnet is a generated view. Community contributions are YAML.

If any of these come up during implementation, **do not include them**. Note them for follow-up.
