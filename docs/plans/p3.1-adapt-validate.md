## 1. Context

`amnezigo validate` (P1.3, merged) reads INI server configs (`awg0.conf`), runs AWG 2.0 invariant checks, and reports findings with stable error codes. The declarative pivot (P2.x) introduces a new primary input format: JSON/Jsonnet manifests (`amnezigo.json` / `amnezigo.jsonnet`) that describe the full network topology — peers, obfuscation profile (either a preset name or explicit parameters), and network settings.

After P2.1+P2.2 land, users will author manifests as their primary configuration format. They need to validate those manifests *before* running `generate` — catching schema errors, address conflicts, and AWG 2.0 invariant violations early. The existing `validate` command cannot help: it only understands INI.

**Two input modes after this PR:**

1. **Manifest validation** (new, primary): `amnezigo validate amnezigo.json` or `amnezigo validate config.jsonnet` — validates the manifest schema, resolves the obfuscation preset (if used), and runs AWG 2.0 invariant checks against the resolved parameters.
2. **Legacy INI validation** (kept): `amnezigo validate awg0.conf` — same behavior as today. No regression.

**Reasons to ship this now (priority order):**

1. **Pre-flight for `generate`**. Users should be able to validate a manifest before committing to generation. If `generate` discovers an invalid manifest mid-pipeline, it aborts after loading — but the error messages come from the generation path, not the purpose-built validation engine with stable codes, severity, and structured output.
2. **Schema enforcement**. Manifests have structural requirements the INI parser never enforced: `version` must be `1`, exactly one server peer must exist, peer addresses must be unique and in the server's subnet. Without `validate`, these only surface as runtime errors during `generate`.
3. **Preset validation**. A typo in `obfuscation.preset` (`"hom-balanced"`) currently only fails at generation time. `validate` catches it with a clear `MNF003` finding referencing the available presets.
4. **Cross-peer invariants**. Duplicate addresses, missing server peers, reserved peer names — these are manifest-level invariants that have no INI analogue. They need their own validation rules.
5. **Uniform tooling surface**. CI scripts that run `amnezigo validate --output json --strict` should work identically regardless of whether the input is INI or manifest. Same exit-code contract, same `Finding` model, same `--strict` / `--quiet` / `--output` flags.

**Current state** (on `dev` HEAD `0bea148`):

- `internal/cli/validate.go:53-93` — `runValidate` opens a file, calls `ParseServerConfigWithOptions`, and runs `ValidateServerConfig`. Hard-wired to INI.
- `validation.go:207-216` — `ValidateServerConfig` orchestrates INI-level checks (required fields, S-prefixes, junk range, header ranges). Operates on `*ServerConfig`.
- No `manifest.go`, no `loader.go` — these arrive with P2.1 and P2.2 respectively.
- `presets.go:123-134` — `GetPreset` returns a `Preset` by name. Used by the manifest's `obfuscation.preset` field.
- Finding model (`Finding`, `Severity`, `Location`) and error codes (`PSC001`..`KEY001`) are stable in `validation.go`.

## 2. Goal

Extend `amnezigo validate` to accept manifest files (`.json` / `.jsonnet`) in addition to INI configs. Auto-detect the format by file extension. For manifests, validate the schema, resolve the obfuscation profile (preset or explicit), and run AWG 2.0 invariant checks on the resolved parameters. Report all findings using the existing `Finding` model with new manifest-specific error codes (`MNF001`-`MNF00N`).

The command remains **read-only**. No mutation, no generation, no file writes.

**In scope (this PR):**

- Format auto-detection in `runValidate`: `.json`/`.jsonnet` → manifest path; `.conf` and everything else → INI path.
- New `ValidateManifest(m *Manifest) []Finding` orchestrator in a new `manifest_validation.go` file.
- Manifest-specific validation rules: version, server peer existence, peer address uniqueness, address-in-subnet, preset validity, explicit obfuscation parameter checks, reserved peer name rejection.
- AWG 2.0 invariant checks on resolved obfuscation parameters (reuse `ValidatePacketSizes`, `ValidateHeaderRange`).
- Location enrichment: manifest findings carry peer name and JSON field path in `Location.Key`.
- All existing INI validation behavior preserved — zero regression.
- Tests for every new rule; round-trip test (valid manifest → 0 findings).
- Updated `docs/cli-reference.md` documenting the dual-format support.

**Explicit out-of-scope (deferred):**

- Dry-run generation during validation (running the full `generate` pipeline in memory to catch MTU budget overflow, I-packet collision). Valuable but doubles the scope. Tracked as P3.1-followup.
- SARIF output format. Same as P1.3 — deferred to CI integration work.
- Jsonnet evaluation errors beyond "file failed to evaluate". Jsonnet syntax errors are surfaced by `LoadManifest` (P2.2) as a single `PSE002` finding; deeper Jsonnet diagnostics are the Jsonnet VM's responsibility.
- `--fix` auto-fix for manifests (e.g., auto-dedup addresses). Not in scope.
- Client config validation (still deferred from P1.3).

## 4. Architecture Decisions

### 4.1 Format auto-detection — file extension, not content sniffing

**Decision**: detect format by file extension in `runValidate`. `.json` and `.jsonnet` → manifest path. Everything else (`.conf`, no extension, unknown extension) → INI path.

**Rationale**:

- Content sniffing (`{` as first byte → JSON) is fragile — INI comments can contain `{`, and a broken JSON file might not start with `{`.
- File extension is unambiguous and matches user expectation. The roadmap specifies `amnezigo.json` / `amnezigo.jsonnet` as the canonical names.
- If a user names their manifest `config.conf`, they get the INI path — that's a user error, not a tool bug. The INI parser will fail on JSON syntax and produce a clear `PSE001` finding.
- Alternative considered: `--format ini|manifest` flag. Rejected for v1 — auto-detection is sufficient; add the flag only if users request it.

### 4.2 New validation file — `manifest_validation.go`, not extending `validation.go`

**Decision**: manifest-specific validation rules live in a new file `manifest_validation.go` in the root package. `validation.go` stays INI-focused.

**Rationale**:

- `validation.go` is currently 313 lines and coherent (all rules operate on `*ServerConfig`). Manifest rules operate on `*Manifest` — different input type, different concerns.
- Separation makes it clear which rules apply to which format.
- Both files share the `Finding` model and can call shared validation primitives (`ValidatePacketSizes`, `ValidateHeaderRange`).
- The file is in the same package (`amnezigo`) — no export boundary issues.

### 4.3 Error code allocation — `MNF` family for manifest-specific findings

**Decision**: manifest-specific findings use the `MNF` (manifest) code family. AWG 2.0 invariant violations reuse existing codes (`PSC001`, `HDR001`, etc.) even when triggered through the manifest path — the underlying rule is the same.

**Initial allocations**:

- `MNF001` — invalid or missing `version` field (must be `1`)
- `MNF002` — no server peer found (no peer with `endpoint` + `listen_port`)
- `MNF003` — unknown preset name (not in `presetRegistry`)
- `MNF004` — duplicate peer address
- `MNF005` — peer address outside server's subnet
- `MNF006` — reserved peer name used (`output`, `.git`, `.github`, etc.)
- `MNF007` — multiple server peers (more than one peer with `endpoint`)
- `MNF008` — empty peers map (no peers defined)
- `MNF009` — client peer has server-only fields (`post_up`, `post_down`, `listen_port`)
- `PSE002` — manifest parse/load error (jsonnet eval failure, JSON syntax error)

Reused from existing allocations (triggered on resolved obfuscation params):

- `PSC001` — pairwise S-prefix size collision
- `PSC002` — junk range contains forbidden size
- `HDR001` — H-range overlaps WG type-ids
- `HDR002` — H-range structurally invalid
- `JNK001` — junk range structurally invalid
- `FLD001` — required field missing (adapted: checks manifest-level required fields)

**Stability contract**: same as P1.3 — codes are stable; changing a code is a breaking change. `Message` and `Detail` are free to evolve.

### 4.4 Preset resolution — validate before and after resolution

**Decision**: when a manifest specifies `obfuscation.preset`, validation does two things:

1. **Before resolution**: check that the preset name exists in `presetRegistry` (`MNF003` if not).
2. **After resolution**: call `Preset.ToServerObfuscation()`, apply any explicit overrides from the manifest, then run `ValidatePacketSizes` and `ValidateHeaderRange` on the resolved `ServerObfuscationConfig`. This catches presets that have been overridden into an invalid state (e.g., user sets `s1: 0, s2: 56` on top of a preset, creating a collision).

**Rationale**:

- Preset-only validation ("does the name exist?") catches typos but misses override-induced violations.
- Post-resolution validation catches everything but requires the resolution step.
- Doing both is cheap and comprehensive.

### 4.5 Explicit-only obfuscation — treat as ad-hoc `ServerObfuscationConfig`

**Decision**: when a manifest specifies explicit obfuscation parameters without a preset, construct a `ServerObfuscationConfig` from the explicit values and validate it through the same `ValidatePacketSizes` / `ValidateHeaderRange` path. If required obfuscation fields are missing (no preset AND no explicit S/H/J values), emit `FLD001` findings for the missing fields.

**Rationale**:

- The manifest must resolve to a concrete obfuscation config for generation to work. Validation should catch incomplete configs before generation.
- Reusing the existing validation primitives avoids duplicating invariant logic.

### 4.6 Location model enrichment — peer name in `Location.Key`

**Decision**: manifest findings use `Location.Key` to carry the JSON field path, including peer name where applicable. Examples:

- `Location{Key: "version"}` — top-level field
- `Location{Key: "peers.phone.address"}` — peer-specific field
- `Location{Key: "obfuscation.preset"}` — obfuscation field
- `Location{Key: "obfuscation.H1"}` — resolved obfuscation parameter

`Location.File` carries the manifest file path. `Location.Line` is `0` (JSON/Jsonnet don't have meaningful line numbers after evaluation — the Jsonnet VM reports line numbers in its own errors, which we surface as `PSE002`).

**Rationale**:

- INI findings use `Location.Line` because INI is line-oriented. Manifests are tree-oriented — field paths are more useful than line numbers.
- The `Location` struct already supports both via `Key` and `Line` fields with `omitempty` — no type changes needed.

### 4.7 `runValidate` branching — early detection, separate code paths

**Decision**: `runValidate` detects the format from the file extension before opening the file. Each path is a self-contained function: `validateINI(cmd, path)` (extracted from current `runValidate`) and `validateManifest(cmd, path)` (new). Both return `[]Finding` to the shared `emitFindings`.

**Rationale**:

- The two paths share no parsing logic — one calls `ParseServerConfigWithOptions`, the other calls `LoadManifest`. Mixing them in one function would create a complex conditional tree.
- Extracting `validateINI` from the current `runValidate` is a pure refactor — zero behavior change.
- Both paths converge at `emitFindings`, which handles `--output`, `--strict`, `--quiet`, and exit codes identically.

### 4.8 Subnet validation — `net.Contains` for address-in-subnet check

**Decision**: parse the server peer's `address` field as `net.IPNet` (CIDR). For each client peer, parse its `address` as `net.IP` and check `serverNet.Contains(clientIP)`. Emit `MNF005` if the client address is outside the server's subnet.

**Rationale**:

- Go's `net` package provides `net.ParseCIDR` and `(*IPNet).Contains` — no custom CIDR logic needed.
- The server peer's address is expected in CIDR notation (`10.0.0.1/24`); client addresses may be CIDR (`10.0.0.2/32`) or bare IP — parse both forms.
- If the server address is not valid CIDR, emit a separate `FLD001` finding for the malformed address rather than silently skipping subnet validation.

```go
func runValidate(cmd *cobra.Command, args []string) error {
    path := args[0]
    findings, err := validateINI(path)
    if err != nil {
        return err
    }
    return emitFindings(cmd.OutOrStdout(), path, findings)
}

func validateINI(path string) ([]amnezigo.Finding, error) {
    f, err := os.Open(path)
    if err != nil {
        return nil, fmt.Errorf("open %q: %w", path, err)
    }
    defer f.Close()

    cfg, warnings, parseErr := amnezigo.ParseServerConfigWithOptions(
        f, amnezigo.ParseOptions{Strict: true})

    var findings []amnezigo.Finding

    for _, w := range warnings {
        findings = append(findings, amnezigo.Finding{
            Severity: amnezigo.SeverityWarning,
            Code:     w.Code,
            Location: amnezigo.Location{File: path, Line: w.Line, Key: w.Key},
            Message:  w.Message,
        })
    }

    if parseErr != nil {
        findings = append(findings, amnezigo.Finding{
            Severity: amnezigo.SeverityError,
            Code:     "PSE001",
            Location: amnezigo.Location{File: path},
            Message:  parseErr.Error(),
        })
    } else {
        for _, ff := range amnezigo.ValidateServerConfig(&cfg) {
            ff.Location.File = path
            findings = append(findings, ff)
        }
    }

    return findings, nil
}
```

```go
package amnezigo

import (
    "fmt"
    "net"
    "sort"
)

// reservedPeerNames contains names that must not be used as peer names
// because they conflict with output directory names or common filesystem entries.
var reservedPeerNames = map[string]bool{
    "output": true, ".git": true, ".github": true,
    ".gitignore": true, "lib": true, "node_modules": true,
}

// ValidateManifest runs every validation rule against a parsed manifest
// and returns all findings. The slice is empty when the manifest is clean.
func ValidateManifest(m *Manifest) []Finding {
    var findings []Finding

    findings = append(findings, validateManifestVersion(m)...)
    findings = append(findings, validateManifestPeers(m)...)
    findings = append(findings, validateManifestObfuscation(m)...)

    return findings
}

func validateManifestVersion(m *Manifest) []Finding {
    if m.Version != 1 {
        return []Finding{{
            Severity: SeverityError,
            Code:     "MNF001",
            Location: Location{Key: "version"},
            Message:  fmt.Sprintf("unsupported manifest version %d (expected 1)", m.Version),
        }}
    }
    return nil
}

func validateManifestPeers(m *Manifest) []Finding {
    var findings []Finding

    // MNF008: empty peers map.
    if len(m.Peers) == 0 {
        return []Finding{{
            Severity: SeverityError,
            Code:     "MNF008",
            Location: Location{Key: "peers"},
            Message:  "no peers defined in manifest",
        }}
    }

    // MNF006: reserved peer names.
    // Sort peer names for deterministic output.
    peerNames := sortedPeerNames(m)
    for _, name := range peerNames {
        if reservedPeerNames[name] {
            findings = append(findings, Finding{
                Severity: SeverityError,
                Code:     "MNF006",
                Location: Location{Key: fmt.Sprintf("peers.%s", name)},
                Message:  fmt.Sprintf("peer name %q is reserved and cannot be used", name),
            })
        }
    }

    // Identify server peers (have endpoint + listen_port).
    var serverNames []string
    for _, name := range peerNames {
        p := m.Peers[name]
        if p.Endpoint != "" && p.ListenPort > 0 {
            serverNames = append(serverNames, name)
        }
    }

    // MNF002: no server peer.
    if len(serverNames) == 0 {
        findings = append(findings, Finding{
            Severity: SeverityError,
            Code:     "MNF002",
            Location: Location{Key: "peers"},
            Message:  "no server peer found (need exactly one peer with endpoint and listen_port)",
        })
    }

    // MNF007: multiple server peers.
    if len(serverNames) > 1 {
        findings = append(findings, Finding{
            Severity: SeverityError,
            Code:     "MNF007",
            Location: Location{Key: "peers"},
            Message:  fmt.Sprintf("multiple server peers found: %v (only one server peer is supported)", serverNames),
        })
    }

    // MNF004: duplicate addresses.
    addrSeen := make(map[string]string) // address → first peer name
    for _, name := range peerNames {
        addr := stripCIDRMask(m.Peers[name].Address)
        if prev, ok := addrSeen[addr]; ok {
            findings = append(findings, Finding{
                Severity: SeverityError,
                Code:     "MNF004",
                Location: Location{Key: fmt.Sprintf("peers.%s.address", name)},
                Message:  fmt.Sprintf("duplicate address %q (also used by peer %q)", m.Peers[name].Address, prev),
            })
        } else {
            addrSeen[addr] = name
        }
    }

    // MNF005: address outside server's subnet.
    if len(serverNames) == 1 {
        serverAddr := m.Peers[serverNames[0]].Address
        _, serverNet, err := net.ParseCIDR(serverAddr)
        if err == nil {
            for _, name := range peerNames {
                if name == serverNames[0] {
                    continue // skip server itself
                }
                peerIP := parseIPFromCIDR(m.Peers[name].Address)
                if peerIP != nil && !serverNet.Contains(peerIP) {
                    findings = append(findings, Finding{
                        Severity: SeverityError,
                        Code:     "MNF005",
                        Location: Location{Key: fmt.Sprintf("peers.%s.address", name)},
                        Message:  fmt.Sprintf("peer address %q is outside server subnet %s", m.Peers[name].Address, serverNet),
                    })
                }
            }
        }
    }

    // MNF009: client peers with server-only fields.
    for _, name := range peerNames {
        p := m.Peers[name]
        if p.Endpoint != "" {
            continue // server peer — these fields are expected
        }
        if p.PostUp != "" || p.PostDown != "" || p.ListenPort > 0 {
            findings = append(findings, Finding{
                Severity: SeverityWarning,
                Code:     "MNF009",
                Location: Location{Key: fmt.Sprintf("peers.%s", name)},
                Message:  fmt.Sprintf("client peer %q has server-only fields (post_up, post_down, or listen_port)", name),
            })
        }
    }

    return findings
}

// sortedPeerNames returns the peer names from a manifest in sorted order
// for deterministic validation output.
func sortedPeerNames(m *Manifest) []string {
    names := make([]string, 0, len(m.Peers))
    for name := range m.Peers {
        names = append(names, name)
    }
    sort.Strings(names)
    return names
}

// stripCIDRMask extracts the IP portion from "10.0.0.1/24" → "10.0.0.1".
func stripCIDRMask(addr string) string {
    ip, _, err := net.ParseCIDR(addr)
    if err != nil {
        // Try parsing as bare IP.
        if parsed := net.ParseIP(addr); parsed != nil {
            return parsed.String()
        }
        return addr // unparseable — pass through, let other rules catch it
    }
    return ip.String()
}

// parseIPFromCIDR extracts the IP from a CIDR string or bare IP.
func parseIPFromCIDR(addr string) net.IP {
    ip, _, err := net.ParseCIDR(addr)
    if err != nil {
        return net.ParseIP(addr)
    }
    return ip
}
```

```go
func validateManifestObfuscation(m *Manifest) []Finding {
    var findings []Finding
    obf := m.Obfuscation

    // Resolve the obfuscation config to validate.
    var resolved ServerObfuscationConfig
    hasPreset := obf.Preset != ""
    hasExplicit := obf.S1 != 0 || obf.S2 != 0 || obf.S3 != 0 || obf.S4 != 0 ||
        obf.Jc != 0 || obf.Jmin != 0 || obf.Jmax != 0 ||
        obf.H1 != "" || obf.H2 != "" || obf.H3 != "" || obf.H4 != ""

    switch {
    case hasPreset:
        // MNF003: check preset exists.
        preset, err := GetPreset(obf.Preset)
        if err != nil {
            findings = append(findings, Finding{
                Severity: SeverityError,
                Code:     "MNF003",
                Location: Location{Key: "obfuscation.preset"},
                Message:  err.Error(),
            })
            return findings // cannot resolve further
        }
        resolved = preset.ToServerObfuscation()

        // Apply explicit overrides on top of preset.
        applyObfuscationOverrides(&resolved, obf)

    case hasExplicit:
        // Build from explicit values.
        resolved = buildExplicitObfuscation(obf)

    default:
        // Neither preset nor explicit — missing obfuscation config.
        findings = append(findings, Finding{
            Severity: SeverityError,
            Code:     "FLD001",
            Location: Location{Key: "obfuscation"},
            Message:  "obfuscation config is empty: set either preset or explicit S/H/J parameters",
        })
        return findings
    }

    // Run AWG 2.0 invariant checks on the resolved config.
    cfg := &ServerConfig{Obfuscation: resolved}
    findings = append(findings, validateSPrefixes(cfg)...)
    findings = append(findings, validateJunkRange(cfg)...)
    findings = append(findings, validateHeaderRanges(cfg)...)

    // Enrich location with "obfuscation." prefix for clarity.
    for i := range findings {
        if findings[i].Location.Key != "" {
            findings[i].Location.Key = "obfuscation." + findings[i].Location.Key
        }
    }

    return findings
}

// applyObfuscationOverrides applies non-zero explicit values from the manifest
// on top of a preset-resolved config.
func applyObfuscationOverrides(resolved *ServerObfuscationConfig, obf ObfuscationManifest) {
    if obf.S1 != 0 { resolved.S1 = obf.S1 }
    if obf.S2 != 0 { resolved.S2 = obf.S2 }
    if obf.S3 != 0 { resolved.S3 = obf.S3 }
    if obf.S4 != 0 { resolved.S4 = obf.S4 }
    if obf.Jc != 0 { resolved.Jc = obf.Jc }
    if obf.Jmin != 0 { resolved.Jmin = obf.Jmin }
    if obf.Jmax != 0 { resolved.Jmax = obf.Jmax }
    if obf.H1 != "" { resolved.H1 = parseHeaderRange(obf.H1) }
    if obf.H2 != "" { resolved.H2 = parseHeaderRange(obf.H2) }
    if obf.H3 != "" { resolved.H3 = parseHeaderRange(obf.H3) }
    if obf.H4 != "" { resolved.H4 = parseHeaderRange(obf.H4) }
}

// buildExplicitObfuscation constructs a ServerObfuscationConfig from explicit
// manifest values.
func buildExplicitObfuscation(obf ObfuscationManifest) ServerObfuscationConfig {
    return ServerObfuscationConfig{
        S1:   obf.S1,
        S2:   obf.S2,
        S3:   obf.S3,
        S4:   obf.S4,
        Jc:   obf.Jc,
        Jmin: obf.Jmin,
        Jmax: obf.Jmax,
        H1:   parseHeaderRange(obf.H1),
        H2:   parseHeaderRange(obf.H2),
        H3:   parseHeaderRange(obf.H3),
        H4:   parseHeaderRange(obf.H4),
    }
}
```

## 7. Validation Checks Catalog

Every check this PR adds or reuses, mapped to the input format.

### New manifest-specific checks

| Code | Severity | Rule | Trigger | Detail |
| --- | --- | --- | --- | --- |
| `MNF001` | error | Invalid `version` field | `version` is not `1` | Future-proofs the schema; version `2` may change structure. |
| `MNF002` | error | No server peer | No peer has both `endpoint` and `listen_port` | A manifest must define exactly one server. |
| `MNF003` | error | Unknown preset name | `obfuscation.preset` not in `presetRegistry` | Typo or user referencing a non-existent preset. |
| `MNF004` | error | Duplicate peer address | Two peers share the same IP (after CIDR mask stripping) | WireGuard cannot route to ambiguous addresses. |
| `MNF005` | error | Peer address outside server subnet | Client peer IP not in server's CIDR network | Client must be in the server's subnet to route correctly. |
| `MNF006` | error | Reserved peer name | Peer name is `output`, `.git`, `.github`, `lib`, etc. | Conflicts with output directory or filesystem entries. |
| `MNF007` | error | Multiple server peers | More than one peer has `endpoint` | Only star topology (single server) is supported. |
| `MNF008` | error | Empty peers map | `peers` is empty | A manifest with no peers is not useful. |
| `MNF009` | warning | Client peer with server-only fields | Client peer has `post_up`, `post_down`, or `listen_port` | These fields only apply to the server peer; likely a misconfiguration. |
| `PSE002` | error | Manifest parse/load error | `LoadManifest` returns error | JSON syntax error, jsonnet evaluation failure, file not found, etc. |

### Reused checks (triggered on resolved obfuscation params)

| Code | Severity | Rule | Source | Detail |
| --- | --- | --- | --- | --- |
| `PSC001` | error | Pairwise S-prefix size collision | `validateSPrefixes` via `ValidatePacketSizes` | Same rule as INI; applied to resolved params. |
| `PSC002` | error | Junk range contains forbidden size | `validateSPrefixes` | Same rule. |
| `HDR001` | error | H-range overlaps WG type-ids | `validateHeaderRanges` | Same rule. |
| `HDR002` | error | H-range structurally invalid | `validateHeaderRanges` | Same rule. |
| `JNK001` | error | Junk range structurally invalid | `validateJunkRange` | Same rule. |
| `FLD001` | error | Required field missing | `validateManifestObfuscation` | Adapted: checks manifest-level obfuscation completeness, not INI PrivateKey/Address/ListenPort. |

## 9. Risks and Edge Cases

| Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- |
| P2.1 types differ from assumptions in this plan | High | Requires updating field access patterns | § 3 documents assumptions explicitly; Step C tests drive the real API. Adjust field names and access when P2.1 lands. Core validation logic (rules, codes, severity) remains unchanged. |
| P2.2 `LoadManifest` signature differs from assumption | Medium | Requires updating `validateManifest` call site | The critical contract is: takes a path, returns a `Manifest` or error. Adapting the call site is trivial. |
| Jsonnet evaluation produces partial output (some fields set, some not) | Low | Incomplete manifest passes validation | `ValidateManifest` checks for required fields (`version`, at least one peer, obfuscation config). Partial output will hit `MNF001`, `MNF002`, `MNF008`, or `FLD001`. |
| User renames manifest to `.conf` | Low | Gets INI parsing, which fails on JSON | INI parser produces `PSE001`. User sees the error and fixes the extension. Acceptable — auto-detection by extension is explicit in the help text. |
| IPv6 addresses in peers | Medium | `net.ParseCIDR` handles IPv6 natively | No special handling needed. `MNF005` subnet check works for both v4 and v6. Verify in tests. |
| Preset with zero S-values (legitimate S1=0) | Low | Override detection uses `!= 0` — cannot override to zero | Document: "to set S1=0 explicitly, do not use a preset". Alternative: use pointer-to-int in P2.1 types — but that is a P2.1 design decision, not this PR's. |
| Map iteration order in peer validation | Low | Non-deterministic finding order | All peer iterations use `sortedPeerNames()` — deterministic ordering by sorted name. |
| `parseHeaderRange` returns zero-value on malformed input | Medium | Zero-value `HeaderRange{Min:0, Max:0}` passes `ValidateHeaderRange` (0 < 4, so it overlaps WG type-ids) | `validateHeaderRanges` correctly catches this as `HDR001`. The finding message will reference the range, making the root cause (malformed H-range string) visible to the user. |
| Performance on large manifests (100+ peers) | Low | Negligible | Validation is O(n^2) for duplicate address check (n = peer count). At 100 peers, that is 10,000 comparisons — sub-millisecond. |
| `--strict` with `MNF009` (warning) on manifests | Low | `MNF009` triggers exit 1 under `--strict` | Correct behavior — same as `KEY001` for INI. Document in help text. |

## 11. Out of Scope (Explicit)

The following are **deliberately excluded** from this PR:

- **Dry-run generation during validation**. Running the full `generate` pipeline in-memory to catch generation-time errors (MTU budget overflow, I-packet collision) would provide deeper validation but doubles the scope. The manifest schema checks and resolved-param invariant checks catch the most common errors. Tracked as P3.1-followup.
- **Jsonnet-level diagnostics**. Jsonnet syntax errors, import resolution failures, and runtime errors are surfaced as a single `PSE002` finding containing the `LoadManifest` error message. Parsing the Jsonnet VM's error output for structured diagnostics is not in scope.
- **Client-config format support**. Still deferred from P1.3.
- **`--fix` for manifests**. Auto-dedup addresses, suggest preset corrections, etc. Not in scope.
- **SARIF output**. Same as P1.3.
- **`--format` flag** for explicit format selection. Auto-detection by extension is sufficient for v1.
- **Manifest diffing** ("what changed since last generate?"). Reserved for a future command.
- **Multi-server topology validation**. P2.x designs for single-server star topology only. `MNF007` rejects multiple server peers.
- **Deep network validation** (e.g., checking that the endpoint hostname resolves, that the listen port is not privileged). Read-only structural checks only.
- **Ordered peer map validation**. If P2.1 uses `map[string]PeerManifest` with a separate `[]string` for ordered keys, validation iterates the map in sorted order for determinism but does not validate the ordering slice.
