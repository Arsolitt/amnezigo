## 1. Context

`amnezigo` is transitioning from an imperative CLI (`init → add → edit → remove → export`) to a declarative config-driven architecture (roadmap decisions 5-10). The user declares the full network topology in a single manifest file (`amnezigo.json` or `.amnezigo.jsonnet`), and `amnezigo generate` produces per-peer output directories.

P2.1 defined the Go types (`Manifest`, `NetworkConfig`, `ObfuscationConfig`, `PeerConfig` in `manifest.go`). This plan implements the **loader** — the function that discovers, reads, optionally evaluates Jsonnet, and unmarshals the manifest into those types. It is the entry point for all declarative commands.

**Why Jsonnet?** JSON is the baseline for simple setups, but Jsonnet enables DRY configuration: shared DNS blocks, per-environment overrides, computed peer addresses, and community-importable library fragments (`lib/presets.libsonnet` in P3.3). This is the same pattern used by cheburbox (`config/load.go:79-123`), which has proven effective in production.

**Reference implementation**: cheburbox's `config/load.go` demonstrates the exact pattern:

- `createJsonnetVM(jpath)` creates a `go-jsonnet` VM with `FileImporter` and `JPaths` (`load.go:80-88`)
- `LoadServerWithJsonnet(dir, jpath)` checks `.cheburbox.jsonnet` first, falls back to `cheburbox.json` (`load.go:93-123`)
- JSON unmarshaling + version validation in both paths (`load.go:61-77`, `load.go:108-115`)

amnezigo's loader follows the same structure, adapted for the single-network model (one manifest, not per-server directories).

**Current state**: no loader exists. `manager.go:25-27` (`Manager.Load()`) reads INI server configs via `LoadServerConfig` / `ParseServerConfig`; that path remains for credential persistence (P2.3 reads existing output configs). The new loader is a separate code path for the manifest format.

## 2. Goal

Ship `LoadManifest(dir string, jpathDirs []string) (Manifest, error)` — a function that discovers and loads a manifest file from a directory, and `LoadManifestFromFile(path string, jpathDirs []string) (Manifest, error)` — a function that loads from an explicit file path.

**In scope (this PR):**

- New file `loader.go` with `LoadManifest`, `LoadManifestFromFile`, `createJsonnetVM` functions.
- New file `loader_test.go` with comprehensive test coverage.
- Fixture files in `testdata/loader/` for test scenarios.
- `go.mod` update: add `github.com/google/go-jsonnet` dependency.
- File discovery: `.amnezigo.jsonnet` takes precedence over `amnezigo.json`.
- Jsonnet VM setup with configurable `--jpath` directories.
- JSON unmarshaling into `Manifest` struct (from P2.1).
- Schema version validation (`version` field must be `1`).
- Clear error messages with file path context.

**Explicit out-of-scope (deferred):**

- CLI command wiring (`--manifest`, `--jpath` flags). That is P2.4's responsibility.
- Manifest semantic validation (peer address uniqueness, server peer existence, obfuscation param ranges). That is P3.1's responsibility.
- Jsonnet native functions. cheburbox doesn't use them (`load.go:80-88`). Defer unless a concrete use case emerges.
- Jsonnet external variables (`--ext-str`, `--ext-code`). Defer.
- Multi-directory discovery (cheburbox discovers per-server dirs). amnezigo is single-network — one manifest per project.
- `lib/presets.libsonnet` generation. That is P3.3.

## 4. Architecture Decisions

### 4.1 Two entry points — `LoadManifest` (discovery) and `LoadManifestFromFile` (explicit)

**Decision**: provide two public functions:

```go
// LoadManifest discovers and loads a manifest from dir.
// Checks for .amnezigo.jsonnet first, then amnezigo.json.
func LoadManifest(dir string, jpathDirs []string) (Manifest, error)

// LoadManifestFromFile loads a manifest from an explicit file path.
// File extension determines evaluation: .jsonnet → Jsonnet VM, otherwise → plain JSON.
func LoadManifestFromFile(path string, jpathDirs []string) (Manifest, error)
```

**Rationale**:

- `LoadManifest` serves the default `amnezigo generate` flow (discover in working dir).
- `LoadManifestFromFile` serves `amnezigo generate --manifest /path/to/file` (explicit path).
- Separating discovery from loading keeps each function focused and testable.
- cheburbox combines both in `LoadServerWithJsonnet(dir, jpath)` because it always operates on directories. amnezigo needs both patterns because `--manifest` can point to a specific file.

### 4.2 File naming — `amnezigo.json` and `.amnezigo.jsonnet`

**Decision**: JSON file is `amnezigo.json` (no dot prefix), Jsonnet file is `.amnezigo.jsonnet` (dot prefix).

**Rationale**:

- Matches the cheburbox pattern: `cheburbox.json` (visible) vs `.cheburbox.jsonnet` (hidden).
- The dot prefix on the Jsonnet file is intentional: Jsonnet is a "source" format that produces JSON. Users who track the Jsonnet file in git may want the JSON output `.gitignore`-d; the dot prefix signals "this is the source, not the artifact".
- `amnezigo.json` without dot prefix: this is both the standalone format for simple setups and the output of Jsonnet evaluation. Visible by default.

### 4.3 Jsonnet VM setup — `FileImporter` with `JPaths`

**Decision**: create the VM with `jsonnet.MakeVM()` and set `vm.Importer` to `&jsonnet.FileImporter{JPaths: jpathDirs}`. No native functions, no external variables.

**Rationale**:

- Direct mirror of cheburbox `config/load.go:80-88`.
- `FileImporter` resolves `import "lib/presets.libsonnet"` relative to the `JPaths` directories.
- `jpathDirs` defaults to `[]string{dir + "/lib"}` when empty (convention: `lib/` relative to the manifest directory). The caller (CLI layer in P2.4) can override via `--jpath` flag.
- Native functions (`NativeFunction`) are not needed: the manifest schema is declarative data, not computation. If a future use case demands them (e.g. IP address arithmetic), add them then.
- External variables (`ExtVar`) are similarly deferred. Environment-based overrides can be achieved with Jsonnet's `std.extVar` once we add `--ext-str` support.

### 4.4 Version validation — checked in the loader, not deferred to a separate validator

**Decision**: the loader validates `version == 1` immediately after unmarshaling. Returns an error if the version is wrong or missing.

**Rationale**:

- cheburbox does this in `loadFromJSON` (`load.go:72-74`) and in the Jsonnet path (`load.go:113-115`). The version check is the most basic structural validation — if the schema version is wrong, nothing downstream can work.
- Separating this from semantic validation (P3.1) is intentional: the loader guarantees the manifest is structurally valid JSON matching schema v1. Semantic validation (peer uniqueness, obfuscation param ranges) is a higher-level concern.
- A zero or missing version produces a clear error: `"amnezigo.json: missing or zero version field"` (mirrors cheburbox's wording).
- An unsupported version produces: `"amnezigo.json: unsupported schema version 2 (expected 1)"`.

### 4.5 Error wrapping — file path always included

**Decision**: every error returned by the loader includes the file path via `fmt.Errorf("...: %w", path, err)`. Jsonnet evaluation errors naturally include file:line from the `go-jsonnet` library.

**Rationale**:

- cheburbox wraps every error with the file path (`load.go:65`, `load.go:104`).
- Jsonnet's error type includes source location (`filename:line:col: message`), which is the main advantage of Jsonnet over JSON for error reporting. The loader passes these through verbatim.
- JSON unmarshal errors from `encoding/json` include byte offset but not line number. This is acceptable for v1 — JSON files are typically small. A follow-up could use a JSON-with-comments parser for better errors, but that's out of scope.

### 4.6 Default `--jpath` — `lib/` relative to manifest directory

**Decision**: when `jpathDirs` is empty or nil, the loader defaults to `[]string{filepath.Join(dir, "lib")}` where `dir` is the manifest's parent directory. This directory does not need to exist — the `FileImporter` simply won't find any imports if it's missing.

**Rationale**:

- Convention from cheburbox: `lib/` is where shared Jsonnet libraries live.
- P3.3 will generate `lib/presets.libsonnet` in this location.
- Not requiring the directory to exist avoids errors for simple JSON-only setups where no imports are used.

### 4.7 Package placement — root `amnezigo` package, not a sub-package

**Decision**: `loader.go` lives in the root `amnezigo` package alongside `parser.go`, `validation.go`, `generator.go`.

**Rationale**:

- The loader produces `Manifest` (defined in `manifest.go`, same package). No cross-package import needed.
- Consistent with the project's flat structure: all domain logic in the root package, CLI wiring in `internal/cli/`.
- A `config/` sub-package (like cheburbox) would force exporting types that are currently package-private. Defer package extraction until P2.4 or later reveals a need.

package amnezigo

import (
    "encoding/json"
    "fmt"
    "os"
    "path/filepath"
    "strings"

    "github.com/google/go-jsonnet"
)

const (
    manifestJSON    = "amnezigo.json"
    manifestJsonnet = ".amnezigo.jsonnet"

    // currentManifestVersion is the only schema version this loader supports.
    // Bump (and add migration logic) when the manifest schema evolves.
    currentManifestVersion = 1
)

// LoadManifest discovers and loads a manifest from dir. It checks for
// .amnezigo.jsonnet first (Jsonnet takes precedence), then amnezigo.json.
// If jpathDirs is nil, it defaults to [dir/lib] for Jsonnet library resolution.
// Returns an error if no manifest file is found or loading fails.
func LoadManifest(dir string, jpathDirs []string) (Manifest, error) {
    jsonnetPath := filepath.Join(dir, manifestJsonnet)
    jsonPath := filepath.Join(dir, manifestJSON)

    _, errJsonnet := os.Stat(jsonnetPath)
    _, errJSON := os.Stat(jsonPath)

    switch {
    case errJsonnet == nil:
        return loadFromJsonnet(jsonnetPath, resolveJpath(dir, jpathDirs))
    case errJSON == nil:
        return loadFromJSON(jsonPath)
    default:
        return Manifest{}, fmt.Errorf(
            "no manifest file found in %s (expected %s or %s)",
            dir, manifestJsonnet, manifestJSON)
    }
}

// LoadManifestFromFile loads a manifest from an explicit file path. File
// extension determines evaluation: .jsonnet → Jsonnet VM, otherwise → plain
// JSON. If jpathDirs is nil, it defaults to [parentDir/lib].
func LoadManifestFromFile(path string, jpathDirs []string) (Manifest, error) {
    dir := filepath.Dir(path)

    if strings.HasSuffix(path, ".jsonnet") {
        return loadFromJsonnet(path, resolveJpath(dir, jpathDirs))
    }
    return loadFromJSON(path)
}

// resolveJpath returns jpathDirs if non-empty, or the default [dir/lib].
func resolveJpath(dir string, jpathDirs []string) []string {
    if len(jpathDirs) > 0 {
        return jpathDirs
    }
    return []string{filepath.Join(dir, "lib")}
}

// loadFromJSON reads and parses a JSON manifest file.
func loadFromJSON(path string) (Manifest, error) {
    data, err := os.ReadFile(path)
    if err != nil {
        return Manifest{}, fmt.Errorf("read %s: %w", path, err)
    }

    var m Manifest
    if err := json.Unmarshal(data, &m); err != nil {
        return Manifest{}, fmt.Errorf("parse %s: %w", path, err)
    }

    if err := validateManifestVersion(path, m.Version); err != nil {
        return Manifest{}, err
    }

    return m, nil
}

// loadFromJsonnet evaluates a Jsonnet file and parses the resulting JSON.
func loadFromJsonnet(path string, jpathDirs []string) (Manifest, error) {
    vm := createJsonnetVM(jpathDirs)
    output, err := vm.EvaluateFile(path)
    if err != nil {
        return Manifest{}, fmt.Errorf("evaluate jsonnet %s: %w", path, err)
    }

    var m Manifest
    if err := json.Unmarshal([]byte(output), &m); err != nil {
        return Manifest{}, fmt.Errorf("parse jsonnet output from %s: %w", path, err)
    }

    if err := validateManifestVersion(path, m.Version); err != nil {
        return Manifest{}, err
    }

    return m, nil
}

// createJsonnetVM creates a Jsonnet VM with the given library search paths.
func createJsonnetVM(jpathDirs []string) *jsonnet.VM {
    vm := jsonnet.MakeVM()
    if len(jpathDirs) > 0 {
        vm.Importer(&jsonnet.FileImporter{
            JPaths: jpathDirs,
        })
    }
    return vm
}

// validateManifestVersion checks that the manifest version is supported.
func validateManifestVersion(path string, version int) error {
    if version == 0 {
        return fmt.Errorf("%s: missing or zero version field", path)
    }
    if version != currentManifestVersion {
        return fmt.Errorf(
            "%s: unsupported schema version %d (expected %d)",
            path, version, currentManifestVersion)
    }
    return nil
}

## 8. Risks and Edge Cases

| Risk | Likelihood | Impact | Mitigation |
| --- | --- | --- | --- |
| P2.1 not merged yet — `Manifest` type doesn't exist | Blocking | Cannot compile | Plan explicitly depends on P2.1; pre-flight check verifies it's on `dev`. |
| `go-jsonnet` version incompatibility | Low | Build failure | Pin to a specific version in `go.mod`. `go-jsonnet` is a mature Google-maintained library with stable API. |
| Jsonnet evaluation timeout on pathological input | Low | Hung process | `go-jsonnet` has no built-in timeout. Acceptable for v1 — manifests are small. If a user creates an infinite loop in Jsonnet, they ctrl-c. Add `vm.MaxStack` if reports emerge. |
| Symlink loops in `--jpath` resolution | Low | Infinite loop | `go-jsonnet` `FileImporter` follows symlinks but has depth limits. Acceptable. |
| Very large manifests (1000+ peers) | Low | Memory | JSON unmarshal into `map[string]PeerConfig` is O(n). Even 10K peers is <1MB of JSON. Acceptable. |
| Race condition: file changes between `os.Stat` and `os.ReadFile` | Very low | Stale error | Standard TOCTOU. Acceptable for a CLI tool — user retries. |
| Windows path separators in `--jpath` | Low | Import failure on Windows | `filepath.Join` handles separators. `go-jsonnet` `FileImporter` uses `os.Open` which handles platform paths. Acceptable. |
| User passes a `.conf` file to `LoadManifestFromFile` | Medium | Confusing error | JSON unmarshal error on INI content is unclear ("invalid character '[' looking for beginning of value"). Consider: detect INI content and return a helpful error. Defer to P3.1 which adds format auto-detection. |
| `lib/` directory doesn't exist | Common | No impact | `FileImporter` returns "file not found" for imports that rely on it. If no imports are used, the missing directory is harmless. |
| JSON with BOM or trailing bytes | Low | Parse error | `encoding/json` handles UTF-8 BOM. Trailing content causes unmarshal error with offset. Acceptable. |

## 10. Out of Scope (Explicit)

The following are **deliberately excluded** from this PR:

- **CLI flag wiring** (`--manifest`, `--jpath`, `--project`). The loader is a library; CLI integration is P2.4's job.
- **Manifest semantic validation** (peer address uniqueness, server peer detection, obfuscation param ranges, preset existence). That is P3.1. The loader only checks structural validity (is it valid JSON? is version 1?).
- **Jsonnet native functions** (`vm.NativeFunction`). cheburbox doesn't use them. No use case yet.
- **Jsonnet external variables** (`vm.ExtVar`, `--ext-str`, `--ext-code`). Useful for environment-based overrides but not needed for v1.
- **Jsonnet top-level arguments** (`vm.TLAVar`). Same as above.
- **Multi-directory discovery** (cheburbox's `Discover` function). amnezigo is single-network — one manifest per project.
- **`lib/presets.libsonnet` generation**. That is P3.3.
- **Format auto-detection for mixed INI/JSON** (`validate` command accepting both formats). That is P3.1.
- **Peer ordering** (preserving insertion order from JSON/Jsonnet). JSON `map[string]` is unordered by spec; if ordering matters, P2.1 should use an ordered map or `[]string` for key order. The loader doesn't add ordering — it passes through whatever `json.Unmarshal` produces.
- **Manifest migration** (converting v0 → v1). No v0 exists; there's nothing to migrate.
- **JSON Schema generation**. P2.1 may include this as optional; the loader doesn't generate schemas.
- **Caching** (memoizing loaded manifests). The loader is called once per `generate` invocation. No need.

If any of these come up during implementation, **do not include them**. Note for the next PR.
